# Linting și golangci-lint — Fundamente

Un **linter** citește codul fără să-l ruleze și semnalează greșeli probabile: erori ignorate, variabile atribuite degeaba, format greșit la `Printf`. `golangci-lint` e unealta standard de facto în Go: rulează zeci de linters într-o singură comandă, cu o singură configurație.

## De ce, dacă am deja compilatorul?

Compilatorul Go e strict (variabile și importuri nefolosite sunt erori), dar acceptă mult cod greșit. Programul de mai jos compilează și rulează, deși are trei probleme pe care un linter le prinde imediat:

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	nume := "Ana"
	nume = "Ion" // valoarea "Ana" nu e folosită niciodată

	f, err := os.CreateTemp("", "demo")
	if err != nil {
		fmt.Println(err)
		return
	}
	defer os.Remove(f.Name())

	f.WriteString("salut") // eroarea întoarsă e ignorată
	f.Close()

	fmt.Printf("%d\n", nume) // %d cu un string
}
```

## Familia de unelte

| Unealtă | Ce face |
|---|---|
| `gofmt` | formatează codul; nu e negociabil în Go |
| `go vet` | inclus în toolchain; greșeli aproape sigure (printf, copierea unui mutex, `cancel` uitat) |
| `staticcheck` | sute de verificări: bug-uri, API-uri depreciate, simplificări, stil |
| `golangci-lint` | **agregator**: rulează `govet`, `staticcheck` și peste 100 de alți linters în paralel, cu cache și o configurație comună |

`golangci-lint` nu înlocuiește `go vet` și `staticcheck`, ci le **include**: `govet` și `staticcheck` sunt doi dintre linterii lui.

## Instalare

Documentația oficială recomandă **binarul precompilat**, cu versiunea fixată:

```bash
# Linux/macOS: binarul în $(go env GOPATH)/bin
curl -sSfL https://golangci-lint.run/install.sh | sh -s -- -b $(go env GOPATH)/bin v2.15.0
# macOS
brew install golangci-lint
golangci-lint version
```

`go install` funcționează, dar nu e recomandat: rezultatul depinde de versiunea locală de Go și de dependențele rezolvate pe mașina ta.

## Prima rulare

```bash
golangci-lint run           # pachetul curent și subpachetele (implicit ./...)
golangci-lint run ./...     # explicit: tot modulul
golangci-lint run ./api/... # doar un subarbore
```

Pe programul de mai sus, rezultatul arată așa:

```text
main.go:17:17: Error return value of `os.Remove` is not checked (errcheck)
main.go:19:15: Error return value of `f.WriteString` is not checked (errcheck)
main.go:20:9: Error return value of `f.Close` is not checked (errcheck)
main.go:22:14: printf: fmt.Printf format %d has arg nume of wrong type string (govet)
main.go:9:2: ineffectual assignment to nume (ineffassign)
5 issues:
* errcheck: 3
* govet: 1
* ineffassign: 1
```

Observă că și `defer os.Remove(...)` apare: `errcheck` nu face excepție pentru `defer`. Când chiar vrei să ignori o eroare, o spui explicit cu `_ =`, ca să se vadă că e o decizie, nu o scăpare.

Fiecare linie are forma **`fișier:linie:coloană: mesaj (linter)`**. Numele linterului din paranteză e important: îl folosești ca să cauți documentația, să configurezi linterul sau să suprimi o alertă.

**Codul de ieșire** e `1` când există probleme și `0` când nu există. Așa oprește CI-ul un build.

## Linterii activi implicit

Fără configurație, `golangci-lint` v2 rulează setul **`standard`**, de cinci linters:

| Linter | Ce prinde |
|---|---|
| `errcheck` | erori întoarse și ignorate (`f.Close()`, `json.Unmarshal(...)` fără `err`) |
| `govet` | analizorii din `go vet`: printf, copylocks, lostcancel, structtag, unreachable... |
| `ineffassign` | atribuiri a căror valoare nu e citită niciodată |
| `staticcheck` | bug-uri (SA), simplificări (S), stil (ST), quick fixes (QF) |
| `unused` | constante, variabile, funcții și tipuri nefolosite |

```bash
golangci-lint linters       # ce e activ și ce e disponibil, cu descrieri
golangci-lint help linters  # toți linterii cunoscuți
```

## Formatare: `golangci-lint fmt`

Din v2, formatterele (`gofmt`, `goimports`, `gofumpt`, `gci`, `golines`) au o comandă separată:

```bash
golangci-lint fmt           # formatează fișierele pe loc
golangci-lint fmt --diff    # arată doar diferențele
```

## Repararea automată: `--fix`

Unii linters știu să-și repare singuri problemele (în `golangci-lint linters` apar marcați `[auto-fix]`):

```bash
golangci-lint run --fix
```

Ce nu se poate repara automat (de exemplu o eroare ignorată, unde doar tu știi ce trebuie făcut) rămâne în raport.

## Repararea programului

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	nume := "Ion"

	f, err := os.CreateTemp("", "demo")
	if err != nil {
		fmt.Println(err)
		return
	}
	defer func() { _ = os.Remove(f.Name()) }() // fișier temporar: eroarea nu contează

	if _, err := f.WriteString("salut"); err != nil {
		fmt.Println("scriere:", err)
		return
	}
	if err := f.Close(); err != nil {
		fmt.Println("închidere:", err)
		return
	}

	fmt.Printf("%s\n", nume)
}
```

## Pe scurt

- Un linter găsește cod care compilează, dar e greșit sau suspect.
- `golangci-lint` rulează mulți linters deodată; `govet` și `staticcheck` sunt incluși.
- Setul implicit (`standard`): `errcheck`, `govet`, `ineffassign`, `staticcheck`, `unused`.
- `golangci-lint run ./...`; ieșirea e `fișier:linie:coloană: mesaj (linter)`, cu cod de ieșire 1 dacă sunt probleme.
- `golangci-lint fmt` formatează, iar `run --fix` aplică reparațiile automate.
- Instalează binarul cu versiunea fixată, nu cu `go install`.
