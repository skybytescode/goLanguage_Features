# Linting și golangci-lint — Avansat

De ce alertele linterilor contează: ce bug real ascunde fiecare tipar semnalat frecvent, cum citești codurile `staticcheck` și `gosec` și cum alegi între zgomot și siguranță.

## Erori comparate cu `==` (`errorlint`)

Din Go 1.13, erorile se **împachetează** cu `%w`. Comparația cu `==` verifică doar stratul exterior, deci eșuează în tăcere de îndată ce cineva adaugă context:

```go
package main

import (
	"errors"
	"fmt"
	"io/fs"
	"os"
)

func citește(cale string) error {
	_, err := os.ReadFile(cale)
	if err != nil {
		return fmt.Errorf("citire config %q: %w", cale, err)
	}
	return nil
}

func main() {
	err := citește("/nu/exista.json")

	fmt.Println("err == fs.ErrNotExist:      ", err == fs.ErrNotExist)          // false
	fmt.Println("errors.Is(err, ErrNotExist):", errors.Is(err, fs.ErrNotExist)) // true

	var pe *fs.PathError
	fmt.Println("errors.As(err, &pe):        ", errors.As(err, &pe), pe.Op)
}
```

`errorlint` semnalează `==`, aserțiunile de tip pe erori (`err.(*fs.PathError)`) și `fmt.Errorf` cu `%v` în loc de `%w`:

```text
comparing with == will fail on wrapped errors. Use errors.Is to check for a specific error (errorlint)
```

## Mutex copiat (`govet` → `copylocks`)

Un receiver valoare copiază structura, cu tot cu mutex-ul. Fiecare apel blochează **altă** copie a mutex-ului, iar modificările se pierd:

```go
package main

import (
	"fmt"
	"sync"
)

type Contor struct {
	mu sync.Mutex
	n  int
}

// Greșit: receiver valoare. Lucrează pe o copie.
func (c Contor) IncGreșit() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.n++
}

func (c *Contor) Inc() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.n++
}

func main() {
	var a, b Contor
	for range 1000 {
		a.IncGreșit()
		b.Inc()
	}
	fmt.Println("receiver valoare: ", a.n) // 0
	fmt.Println("receiver pointer: ", b.n) // 1000
}
```

```text
copylocks: IncGreșit passes lock by value: demo.Contor contains sync.Mutex (govet)
```

Aceeași regulă acoperă `sync.WaitGroup`, `sync.Once`, `atomic.Int64` și orice tip care conține unul dintre ele: `range` peste un slice de astfel de structuri, transmiterea lor prin valoare, returnarea lor.

## Variabile umbrite (`govet` → `shadow`)

`:=` într-un bloc interior creează o variabilă **nouă**, cu același nume. Eroarea atribuită înăuntru nu ajunge afară:

```go
package main

import (
	"errors"
	"fmt"
)

func pas(i int) (int, error) {
	if i == 2 {
		return 0, errors.New("pasul 2 a eșuat")
	}
	return i * 10, nil
}

func rulează() error {
	var err error
	for i := range 3 {
		if i > 0 {
			_, err := pas(i) // err NOU, vizibil doar în acest bloc
			if err != nil {
				fmt.Println("în buclă:", err)
			}
		}
	}
	return err // mereu nil
}

func main() {
	fmt.Println("rezultat:", rulează())
}
```

`shadow` e un analizor **opțional** al lui `go vet`; îl activezi cu `linters.settings.govet.enable: [shadow]`. E dezactivat implicit pentru că umbrirea e adesea intenționată (`if err := f(); err != nil`), deci produce zgomot.

## Atribuiri inutile (`ineffassign`, `staticcheck` SA4006)

O valoare scrisă și apoi suprascrisă fără să fie citită indică de obicei o **ramură uitată** sau o eroare neverificată:

```go,ignore
rezultat, err := pas1()
rezultat, err = pas2(rezultat) // err de la pas1 n-a fost verificat niciodată
if err != nil {
	return err
}
```

## Codurile `staticcheck`

`staticcheck` grupează verificările după prefix; codul apare la începutul mesajului:

| Prefix | Categorie | Exemple |
|---|---|---|
| `SA` | bug-uri (static analysis) | SA1019 API depreciat, SA4006 valoare nefolosită, SA5011 dereferențiere nil posibilă, SA1012 `context` nil |
| `S` | simplificări (fostul `gosimple`) | S1002 `if ok == true`, S1011 `append` în buclă → `append(a, b...)` |
| `ST` | stil (fostul `stylecheck`) | ST1005 mesaj de eroare cu majusculă sau punct la final |
| `QF` | quick fixes | QF1003 lanț de `if`-uri → `switch` |

```text
main.go:12:5: S1002: should omit comparison to bool constant, can be simplified to ok (staticcheck)
main.go:19:7: SA1019: strings.Title has been deprecated since Go 1.18 ... Use golang.org/x/text/cases instead. (staticcheck)
```

Verificările se aleg individual:

```yaml
linters:
  settings:
    staticcheck:
      checks: ["all", "-ST1000", "-ST1003"]   # toate, fără comentariul de pachet și numele
```

## Codurile `gosec`

| Cod | Problema |
|---|---|
| G101 | credențiale scrise direct în cod |
| G104 | erori neverificate (se suprapune cu `errcheck`) |
| G107 | cerere HTTP cu URL variabil (risc de SSRF) |
| G201 / G202 | SQL construit cu `fmt.Sprintf` sau prin concatenare (SQL injection) |
| G204 | `exec.Command` cu argumente variabile |
| G304 | fișier deschis cu o cale variabilă (path traversal) |
| G301 / G302 / G306 | permisiuni prea largi pentru directoare și fișiere |
| G401 / G501 | criptografie slabă: MD5, SHA1, DES |
| G402 | `tls.Config{InsecureSkipVerify: true}` |
| G404 | `math/rand` folosit unde e nevoie de `crypto/rand` |
| G115 | conversie între întregi cu posibil overflow (`int` → `int32`) |

```text
main.go:4:2: G501: Blocklisted import crypto/md5: weak cryptographic primitive (gosec)
main.go:20:30: G401: Use of weak cryptographic primitive (gosec)
```

`gosec` are multe alarme false (de exemplu G304 pe o cale venită din configurație, nu de la utilizator). Exclude regula **pe linie**, cu justificare, nu global:

```go,ignore
data, err := os.ReadFile(cale) //nolint:gosec // G304: calea vine din flag-ul -config, nu de la client
```

## Resurse neînchise (`bodyclose`, `sqlclosecheck`, `rowserrcheck`)

```go,ignore
resp, err := http.Get(url)
if err != nil {
	return err
}
defer resp.Body.Close() // fără asta: conexiunea nu revine în pool, iar sub sarcină rămâi fără descriptori

rows, err := db.QueryContext(ctx, q)
if err != nil {
	return err
}
defer rows.Close()
for rows.Next() {
	// ...
}
return rows.Err() // erorile din timpul iterării apar doar aici
```

## Erori „înghițite” (`nilerr`) și `nil, nil` (`nilnil`)

```go,ignore
if err != nil {
	return nil // nilerr: eroarea e verificată, apoi aruncată
}

func Găsește(id int) (*User, error) {
	return nil, nil // nilnil: apelantul trebuie să verifice ambele valori ca să afle „nu există”
}
```

Varianta idiomatică: o eroare sentinelă (`ErrNotFound`) sau un rezultat `(User, bool)`.

## Linters sintactici și linters cu tipuri

Unii linters au nevoie doar de **arborele sintactic** (AST): `misspell`, `lll`, `godot`, `whitespace`. Sunt rapizi și apar marcați `[fast]`. Alții au nevoie de **informații de tip**: `errcheck` trebuie să știe că `f.Close()` întoarce `error`, iar `copylocks` că un câmp e `sync.Mutex`. Aceștia cer încărcarea și verificarea de tip a tuturor pachetelor și a dependențelor lor, ceea ce costă timp și memorie.

Consecințe:

- `golangci-lint run --fast-only` rulează doar linterii sintactici: util într-un hook pre-commit.
- Dacă codul **nu compilează**, linterii cu tipuri nu pot rula. `golangci-lint` raportează atunci erorile de compilare (`typecheck`), iar acelea se repară primele.
- Build tags contează: un fișier cu `//go:build linux` nu e analizat pe macOS decât cu `--build-tags` sau `GOOS=linux`.

## Zgomot vs. siguranță

Fiecare linter are un cost: alarme false, timp de rulare și `//nolint` prin cod. Criteriile de alegere:

1. **Prinde bug-uri reale?** `errcheck`, `govet`, `staticcheck`, `errorlint`, `bodyclose`: da, activează-le.
2. **Impune o regulă pe care echipa o vrea?** `revive`, `gocritic`, `exhaustive`: activează-le, configurează-le.
3. **E doar gust?** `varnamelen`, `nlreturn`, `wsl`, `mnd`, `lll` strict: doar dacă echipa e de acord, altfel produc `//nolint` peste tot.

O alertă ignorată sistematic e mai rea decât un linter dezactivat: învață echipa să nu se uite la raport. Un raport curat, cu zero alerte, e singurul care rămâne util în timp.

## Pe scurt

- `errorlint`: `errors.Is`/`errors.As` și `%w`, nu `==` și aserțiuni de tip pe erori.
- `copylocks`: un mutex copiat protejează o copie; folosește receiver pointer.
- `shadow`: `:=` în bloc interior creează o variabilă nouă; erorile se pierd.
- `staticcheck`: SA = bug, S = simplificare, ST = stil, QF = quick fix; `checks` le alege.
- `gosec`: coduri Gxxx; suprimă pe linie, cu motiv.
- Linterii cu tipuri au nevoie de cod care compilează; `--fast-only` pentru verificări rapide.
