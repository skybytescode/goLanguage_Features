# Linting and golangci-lint — Advanced

Why linter reports matter: the real bug behind each commonly flagged pattern, how to read `staticcheck` and `gosec` codes, and how to choose between noise and safety.

## Errors compared with `==` (`errorlint`)

Since Go 1.13, errors are **wrapped** with `%w`. Comparing with `==` only checks the outer layer, so it silently fails as soon as someone adds context:

```go
package main

import (
	"errors"
	"fmt"
	"io/fs"
	"os"
)

func load(path string) error {
	_, err := os.ReadFile(path)
	if err != nil {
		return fmt.Errorf("reading config %q: %w", path, err)
	}
	return nil
}

func main() {
	err := load("/does/not/exist.json")

	fmt.Println("err == fs.ErrNotExist:      ", err == fs.ErrNotExist)          // false
	fmt.Println("errors.Is(err, ErrNotExist):", errors.Is(err, fs.ErrNotExist)) // true

	var pe *fs.PathError
	fmt.Println("errors.As(err, &pe):        ", errors.As(err, &pe), pe.Op)
}
```

`errorlint` flags `==`, type assertions on errors (`err.(*fs.PathError)`) and `fmt.Errorf` with `%v` instead of `%w`:

```text
comparing with == will fail on wrapped errors. Use errors.Is to check for a specific error (errorlint)
```

## A copied mutex (`govet` → `copylocks`)

A value receiver copies the struct, mutex included. Every call locks a **different** copy of the mutex, and the changes are lost:

```go
package main

import (
	"fmt"
	"sync"
)

type Counter struct {
	mu sync.Mutex
	n  int
}

// Wrong: value receiver. It works on a copy.
func (c Counter) IncWrong() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.n++
}

func (c *Counter) Inc() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.n++
}

func main() {
	var a, b Counter
	for range 1000 {
		a.IncWrong()
		b.Inc()
	}
	fmt.Println("value receiver:  ", a.n) // 0
	fmt.Println("pointer receiver:", b.n) // 1000
}
```

```text
copylocks: IncWrong passes lock by value: demo.Counter contains sync.Mutex (govet)
```

The same rule covers `sync.WaitGroup`, `sync.Once`, `atomic.Int64` and any type that contains one of them: `range` over a slice of such structs, passing them by value, returning them.

## Shadowed variables (`govet` → `shadow`)

`:=` in an inner block creates a **new** variable with the same name. The error assigned inside never reaches the outside:

```go
package main

import (
	"errors"
	"fmt"
)

func step(i int) (int, error) {
	if i == 2 {
		return 0, errors.New("step 2 failed")
	}
	return i * 10, nil
}

func run() error {
	var err error
	for i := range 3 {
		if i > 0 {
			_, err := step(i) // a NEW err, visible only in this block
			if err != nil {
				fmt.Println("in the loop:", err)
			}
		}
	}
	return err // always nil
}

func main() {
	fmt.Println("result:", run())
}
```

`shadow` is an **optional** `go vet` analyzer; you enable it with `linters.settings.govet.enable: [shadow]`. It's off by default because shadowing is often intentional (`if err := f(); err != nil`), so it's noisy.

## Useless assignments (`ineffassign`, `staticcheck` SA4006)

A value that is written and then overwritten without being read usually points to a **forgotten branch** or an unchecked error:

```go,ignore
result, err := step1()
result, err = step2(result) // the err from step1 was never checked
if err != nil {
	return err
}
```

## `staticcheck` codes

`staticcheck` groups its checks by prefix; the code is at the start of the message:

| Prefix | Category | Examples |
|---|---|---|
| `SA` | bugs (static analysis) | SA1019 deprecated API, SA4006 unused value, SA5011 possible nil dereference, SA1012 nil `context` |
| `S` | simplifications (formerly `gosimple`) | S1002 `if ok == true`, S1011 `append` in a loop → `append(a, b...)` |
| `ST` | style (formerly `stylecheck`) | ST1005 error string capitalized or ending in punctuation |
| `QF` | quick fixes | QF1003 an `if` chain → `switch` |

```text
main.go:12:5: S1002: should omit comparison to bool constant, can be simplified to ok (staticcheck)
main.go:19:7: SA1019: strings.Title has been deprecated since Go 1.18 ... Use golang.org/x/text/cases instead. (staticcheck)
```

Checks can be selected individually:

```yaml
linters:
  settings:
    staticcheck:
      checks: ["all", "-ST1000", "-ST1003"]   # everything, minus the package comment and naming
```

## `gosec` codes

| Code | Problem |
|---|---|
| G101 | credentials hardcoded in source |
| G104 | unchecked errors (overlaps with `errcheck`) |
| G107 | HTTP request with a variable URL (SSRF risk) |
| G201 / G202 | SQL built with `fmt.Sprintf` or concatenation (SQL injection) |
| G204 | `exec.Command` with variable arguments |
| G304 | file opened from a variable path (path traversal) |
| G301 / G302 / G306 | permissions too broad for directories and files |
| G401 / G501 | weak cryptography: MD5, SHA1, DES |
| G402 | `tls.Config{InsecureSkipVerify: true}` |
| G404 | `math/rand` where `crypto/rand` is needed |
| G115 | integer conversion that may overflow (`int` → `int32`) |

```text
main.go:4:2: G501: Blocklisted import crypto/md5: weak cryptographic primitive (gosec)
main.go:20:30: G401: Use of weak cryptographic primitive (gosec)
```

`gosec` has plenty of false positives (G304 on a path that comes from configuration, not from a user, for example). Exclude the rule **per line**, with a justification, not globally:

```go,ignore
data, err := os.ReadFile(path) //nolint:gosec // G304: the path comes from the -config flag, not from a client
```

## Unclosed resources (`bodyclose`, `sqlclosecheck`, `rowserrcheck`)

```go,ignore
resp, err := http.Get(url)
if err != nil {
	return err
}
defer resp.Body.Close() // without it the connection never returns to the pool, and under load you run out of descriptors

rows, err := db.QueryContext(ctx, q)
if err != nil {
	return err
}
defer rows.Close()
for rows.Next() {
	// ...
}
return rows.Err() // errors during iteration only show up here
```

## Swallowed errors (`nilerr`) and `nil, nil` (`nilnil`)

```go,ignore
if err != nil {
	return nil // nilerr: the error is checked, then thrown away
}

func Find(id int) (*User, error) {
	return nil, nil // nilnil: the caller must check both values to learn "not found"
}
```

The idiomatic alternative: a sentinel error (`ErrNotFound`) or a `(User, bool)` result.

## Syntactic linters and type-aware linters

Some linters only need the **syntax tree** (AST): `misspell`, `lll`, `godot`, `whitespace`. They're fast and marked `[fast]`. Others need **type information**: `errcheck` must know that `f.Close()` returns an `error`, and `copylocks` that a field is a `sync.Mutex`. These require loading and type-checking every package and its dependencies, which costs time and memory.

Consequences:

- `golangci-lint run --fast-only` runs only the syntactic linters: handy in a pre-commit hook.
- If the code **doesn't compile**, type-aware linters can't run. `golangci-lint` then reports the compile errors (`typecheck`), and those get fixed first.
- Build tags matter: a file with `//go:build linux` isn't analyzed on macOS unless you pass `--build-tags` or `GOOS=linux`.

## Noise vs. safety

Every linter has a cost: false positives, run time, and `//nolint` comments in the code. How to choose:

1. **Does it catch real bugs?** `errcheck`, `govet`, `staticcheck`, `errorlint`, `bodyclose`: yes, enable them.
2. **Does it enforce a rule the team wants?** `revive`, `gocritic`, `exhaustive`: enable and configure them.
3. **Is it just taste?** `varnamelen`, `nlreturn`, `wsl`, strict `mnd` or `lll`: only if the team agrees, otherwise they breed `//nolint` everywhere.

A report that is systematically ignored is worse than a disabled linter: it teaches the team not to look at the output. A clean report, with zero issues, is the only kind that stays useful over time.

## In short

- `errorlint`: `errors.Is`/`errors.As` and `%w`, not `==` and type assertions on errors.
- `copylocks`: a copied mutex protects a copy; use a pointer receiver.
- `shadow`: `:=` in an inner block creates a new variable; errors get lost.
- `staticcheck`: SA = bug, S = simplification, ST = style, QF = quick fix; `checks` selects them.
- `gosec`: Gxxx codes; suppress per line, with a reason.
- Type-aware linters need compiling code; `--fast-only` for quick checks.
