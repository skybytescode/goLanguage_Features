# Pointers — Fundamentals

A **pointer** holds the memory address of a value. Through it you can read or modify the value at that address. Go has pointers, but no pointer arithmetic, so they're much simpler (and safer) than in C.

## `&` and `*`

- `&x` means "the address of `x`".
- `*p` means "the value at address `p`".
- `*int` is the type "pointer to `int`".

```go
package main

import "fmt"

func main() {
	x := 10
	p := &x // p has type *int and points to x

	fmt.Println(*p) // 10: read through the pointer
	*p = 20         // write through the pointer
	fmt.Println(x)  // 20: x has changed
}
```

## Why we need pointers: functions receive copies

In Go, arguments are always **copied**. A function that takes an `int` works on a copy and can't change the caller's variable. With a pointer, it can:

```go
package main

import "fmt"

func doubleCopy(n int) {
	n *= 2 // only changes the local copy
}

func double(n *int) {
	*n *= 2 // changes the original value
}

func main() {
	a := 5
	doubleCopy(a)
	fmt.Println(a) // 5

	double(&a)
	fmt.Println(a) // 10
}
```

## `nil`

The zero value of a pointer is `nil`: it points nowhere. Reading through `nil` stops the program with a **panic**:

```go,panic
package main

import "fmt"

func main() {
	var p *int
	fmt.Println(p == nil) // true
	fmt.Println(*p)       // panic: invalid memory address or nil pointer dereference
}
```

Check pointers that may be `nil` before using them.

## Pointers to structs

For structs, Go dereferences automatically: you write `p.Name`, not `(*p).Name`.

```go
package main

import "fmt"

type Person struct {
	Name string
	Age  int
}

func birthday(p *Person) {
	p.Age++ // same as (*p).Age++
}

func main() {
	ana := Person{Name: "Ana", Age: 30}
	birthday(&ana)
	fmt.Println(ana.Age) // 31

	ion := &Person{Name: "Ion"} // & directly on a struct literal
	ion.Age = 25
	fmt.Println(*ion)
}
```

## `new`

`new(T)` allocates a zero value of type `T` and returns a pointer to it:

```go
package main

import "fmt"

func main() {
	p := new(int) // *int, pointing to a 0
	*p = 42
	fmt.Println(*p)
}
```

In practice, `&T{...}` is used far more than `new(T)`, because you can also set field values.

## No pointer arithmetic

In Go you can't write `p++` to move to the next element in memory. That removes a whole class of bugs (reading outside allocated memory). For collections you use slices.

```go,compile_fail
package main

func main() {
	x := [3]int{1, 2, 3}
	p := &x[0]
	p++ // error: invalid operation: p++ (non-numeric type *int)
}
```

## Summary

- `&x` takes the address, `*p` reads or writes the value at the address.
- Arguments are copied; a pointer lets you modify the original.
- Dereferencing a `nil` pointer panics.
- With structs, `p.Field` works directly on the pointer.
- There's no pointer arithmetic.
