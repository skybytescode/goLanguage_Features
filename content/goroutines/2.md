# Goroutines — Practician

Pornirea unei goroutine e ușoară. Greu e să știi **când se oprește**, câte rulează simultan și ce se întâmplă cu erorile și panic-urile ei. La nivelul acesta: cursele de date, scurgerile de goroutines, limitarea concurenței și colectarea erorilor.

## Cursele de date și `-race`

O **cursă de date** apare când două goroutines accesează aceeași variabilă, cel puțin una scrie și nu există sincronizare. Rezultatul e nedefinit:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	contor := 0
	var wg sync.WaitGroup
	for range 1000 {
		wg.Go(func() {
			contor++ // CURSĂ: citire + scriere nesincronizate
		})
	}
	wg.Wait()
	fmt.Println(contor) // adesea mai puțin de 1000
}
```

Detectorul de curse le găsește la rulare:

```bash
go run -race .
go test -race ./...
```

Rulează testele cu `-race` în CI. Soluțiile sunt un `sync.Mutex`, un `atomic.Int64` (vezi [Sync și atomic](../../sync/2/)) sau channels.

## Scurgeri de goroutines

O goroutine blocată pentru totdeauna (pe un channel pe care nu mai scrie nimeni, de exemplu) nu e colectată de GC. Ea și tot ce referă rămân în memorie:

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func cautaPrimul(surse []string) string {
	rez := make(chan string) // FĂRĂ buffer: e problema
	for _, s := range surse {
		go func() {
			rez <- "răspuns de la " + s // doar primul e citit; restul rămân blocați
		}()
	}
	return <-rez
}

func main() {
	fmt.Println(cautaPrimul([]string{"a", "b", "c"}))
	time.Sleep(10 * time.Millisecond)
	fmt.Println("goroutines active:", runtime.NumGoroutine()) // 3: main + 2 blocate
}
```

Corecția aici: `make(chan string, len(surse))`, ca toate trimiterile să reușească. În general: **fiecare goroutine pe care o pornești trebuie să aibă o cale clară de terminare**, de obicei prin `context` (vezi [Context](../../context/2/)).

## Limitarea concurenței

Pornirea a 10.000 de goroutines care deschid conexiuni simultan poate epuiza descriptorii de fișiere sau supraîncărca un server. Un channel cu buffer funcționează ca **semafor**:

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

func main() {
	const maxSimultan = 3
	sem := make(chan struct{}, maxSimultan)
	var activ, maxim atomic.Int32
	var wg sync.WaitGroup

	for range 10 {
		wg.Go(func() {
			sem <- struct{}{}        // ocupă un loc (blochează dacă sunt 3)
			defer func() { <-sem }() // eliberează locul

			n := activ.Add(1)
			for {
				m := maxim.Load()
				if n <= m || maxim.CompareAndSwap(m, n) {
					break
				}
			}
			time.Sleep(10 * time.Millisecond) // „lucrul”
			activ.Add(-1)
		})
	}
	wg.Wait()
	fmt.Println("maxim simultan:", maxim.Load()) // 3
}
```

Alternativa clasică e un **worker pool**: un număr fix de goroutines care citesc sarcini dintr-un channel. Exemplu complet în [Channels](../../channels/2/).

## Colectarea erorilor

Goroutines nu întorc erori. Un tipar simplu: fiecare scrie rezultatul (sau eroarea) pe poziția ei într-un slice prealocat — poziții diferite, deci fără cursă:

```go
package main

import (
	"errors"
	"fmt"
	"sync"
)

func proceseaza(id int) error {
	if id == 2 {
		return fmt.Errorf("sarcina %d: eșuată", id)
	}
	return nil
}

func main() {
	sarcini := []int{1, 2, 3, 4}
	erori := make([]error, len(sarcini))
	var wg sync.WaitGroup
	for i, id := range sarcini {
		wg.Go(func() {
			erori[i] = proceseaza(id) // fiecare goroutine are indexul ei
		})
	}
	wg.Wait()
	if err := errors.Join(erori...); err != nil {
		fmt.Println("erori:", err)
	}
}
```

Pentru cazul „oprește tot la prima eroare”, pachetul `golang.org/x/sync/errgroup` combină `WaitGroup`, prima eroare și anularea printr-un `context`, plus limitarea concurenței cu `SetLimit`:

```go,ignore
g, ctx := errgroup.WithContext(ctx)
g.SetLimit(8)
for _, url := range urls {
	g.Go(func() error {
		return descarca(ctx, url)
	})
}
if err := g.Wait(); err != nil { ... } // prima eroare; ctx e anulat pentru ceilalți
```

## Panic într-o goroutine

Un panic nerecuperat într-o goroutine **oprește tot programul**. Goroutines pornite de un server sau de o bibliotecă au nevoie de propriul `recover` dacă nu vrei asta:

```go
package main

import (
	"fmt"
	"sync"
)

func sigur(wg *sync.WaitGroup, f func()) {
	wg.Go(func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Println("goroutine recuperată:", r)
			}
		}()
		f()
	})
}

func main() {
	var wg sync.WaitGroup
	sigur(&wg, func() { panic("ups") })
	wg.Wait()
	fmt.Println("programul continuă")
}
```

## Pe scurt

- Rulează mereu testele cu `-race`.
- Fiecare goroutine trebuie să aibă o cale de terminare; altfel e o scurgere.
- Un channel cu buffer e un semafor simplu pentru limitarea concurenței.
- Erorile se colectează pe poziții separate sau cu `errgroup`.
- Un panic într-o goroutine oprește tot procesul.
