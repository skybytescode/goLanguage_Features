# Goroutines — Fundamentals

A **goroutine** is a function that runs concurrently with the rest of the program. Starting one costs very little (a few kilobytes of memory), so a Go program can have tens of thousands or even millions of goroutines at once.

## The `go` keyword

Put `go` in front of a function call, and the function starts in a new goroutine. The call doesn't wait for it to finish:

```go
package main

import (
	"fmt"
	"time"
)

func greet(name string) {
	fmt.Println("hello,", name)
}

func main() {
	go greet("Ana") // starts concurrently
	go greet("Ion")
	time.Sleep(100 * time.Millisecond) // ONLY for the demo: a crude wait
	fmt.Println("done")
}
```

The order of the "hello" messages can differ on every run.

## When `main` returns, everything stops

The program exits when `main` returns, **without** waiting for the other goroutines:

```go
package main

import "fmt"

func main() {
	go fmt.Println("I probably won't get to run")
	fmt.Println("main is done")
}
```

The `time.Sleep` in the first example is a bad solution: you don't know how long to wait. The right solution is `sync.WaitGroup`.

## `sync.WaitGroup`: wait for completion

A `WaitGroup` counts active goroutines. Since Go 1.25, its `Go` method starts the goroutine and counts it automatically; `Wait` blocks until all have finished:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup
	for i := range 3 {
		wg.Go(func() {
			fmt.Println("worker", i, "finished")
		})
	}
	wg.Wait() // waits for all 3
	fmt.Println("all finished")
}
```

In older code you'll see the manual form, with `Add` and `Done`:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup
	for i := range 3 {
		wg.Add(1) // before go!
		go func() {
			defer wg.Done()
			fmt.Println("worker", i)
		}()
	}
	wg.Wait()
}
```

`Add` must be called **before** `go`, otherwise `Wait` might see the counter at 0 and return too early.

## Anonymous goroutines

Most often, the goroutine is an anonymous function. Since Go 1.22, every loop iteration has its own `i` variable, so capturing it is safe.

## Concurrency is not parallelism

- **Concurrency**: several tasks make progress over the same period (the program's structure).
- **Parallelism**: several tasks run at exactly the same moment, on different cores.

Go runs goroutines in parallel on all available cores (`runtime.GOMAXPROCS`), but your program must be correct even if there were a single core.

```go
package main

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Println("cores:", runtime.NumCPU())
	fmt.Println("GOMAXPROCS:", runtime.GOMAXPROCS(0)) // 0 = just read the value
}
```

## Communicating between goroutines

Goroutines don't return values. To send results back, you use **channels** (the next topic) or a variable protected by a mutex. The Go proverb:

> Don't communicate by sharing memory; share memory by communicating.

```go
package main

import "fmt"

func main() {
	results := make(chan int)
	for i := 1; i <= 3; i++ {
		go func() {
			results <- i * i // send the result
		}()
	}
	sum := 0
	for range 3 {
		sum += <-results // receive one result
	}
	fmt.Println("sum of squares:", sum) // 14
}
```

## Summary

- `go f()` starts `f` concurrently, without waiting.
- The program stops when `main` returns.
- `sync.WaitGroup` (`wg.Go` + `wg.Wait`) waits for goroutines.
- Goroutines are cheap: you can have a great many.
- Results are sent through channels.
