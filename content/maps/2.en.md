# Maps — Practitioner

Maps have a few surprising rules: their elements aren't addressable, they're reference types, and they aren't safe for concurrent access. The `maps` package and a few patterns cover the rest of everyday needs.

## Maps are references

A map variable holds a pointer to the internal structure. Copying the variable or passing it as an argument does **not** copy the data:

```go
package main

import "fmt"

func add(m map[string]int) {
	m["new"] = 1
}

func main() {
	a := map[string]int{"x": 1}
	b := a // the same map
	b["y"] = 2
	add(a)
	fmt.Println(len(a), len(b)) // 3 3
}
```

For an independent copy, use `maps.Clone` (a shallow copy: pointer or slice values are still shared).

## Map elements aren't addressable

You can't directly modify a field of a struct stored as a value:

```go,compile_fail
package main

type Point struct{ X, Y int }

func main() {
	m := map[string]Point{"a": {1, 2}}
	m["a"].X = 10 // error: cannot assign to struct field m["a"].X in map
}
```

Two solutions:

```go
package main

import "fmt"

type Point struct{ X, Y int }

func main() {
	// 1. read, modify, write back
	m := map[string]Point{"a": {1, 2}}
	p := m["a"]
	p.X = 10
	m["a"] = p

	// 2. store pointers
	mp := map[string]*Point{"a": {1, 2}}
	mp["a"].X = 10

	fmt.Println(m["a"], *mp["a"])
}
```

## Sets

Go has no set type. You use a map with `struct{}` values (zero bytes) or `bool` (more readable when checking):

```go
package main

import "fmt"

func main() {
	seen := map[string]struct{}{}
	for _, s := range []string{"a", "b", "a", "c", "b"} {
		if _, ok := seen[s]; ok {
			fmt.Println("duplicate:", s)
			continue
		}
		seen[s] = struct{}{}
	}
	fmt.Println(len(seen)) // 3
}
```

## The `maps` package

```go
package main

import (
	"fmt"
	"maps"
	"slices"
)

func main() {
	m := map[string]int{"b": 2, "a": 1, "c": 3}

	keys := slices.Sorted(maps.Keys(m)) // sorted keys (Go 1.23)
	fmt.Println(keys)                   // [a b c]

	c := maps.Clone(m)
	c["d"] = 4
	fmt.Println(maps.Equal(m, c)) // false

	maps.DeleteFunc(c, func(k string, v int) bool { return v%2 == 0 })
	fmt.Println(c) // map[a:1 c:3]

	// a map from pairs
	inv := maps.Collect(func(yield func(int, string) bool) {
		for k, v := range m {
			if !yield(v, k) {
				return
			}
		}
	})
	fmt.Println(inv[2]) // b
}
```

`maps.Keys` and `maps.Values` return **iterators** (`iter.Seq`), not slices. `slices.Collect` or `slices.Sorted` turn them into slices. Details in [Range and iterators](../../iteratori/2/).

## Preallocation

If you know how many elements there will be, `make(map[K]V, n)` avoids repeated growth:

```go
package main

import "fmt"

func main() {
	n := 10000
	squares := make(map[int]int, n)
	for i := range n {
		squares[i] = i * i
	}
	fmt.Println(len(squares))
}
```

## `clear`

`clear(m)` (Go 1.21) removes every element, keeping the allocated memory for reuse. Before, you'd get the same effect with a loop of `delete`s.

## Maps aren't safe for goroutines

Concurrent reads are fine. A **write** concurrent with any other access is a data race, and the runtime often detects it and stops the program with `fatal error: concurrent map writes` (it can't be caught with `recover`).

The usual solution is a mutex:

```go
package main

import (
	"fmt"
	"sync"
)

type Counters struct {
	mu sync.Mutex
	m  map[string]int
}

func (c *Counters) Inc(k string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.m[k]++
}

func main() {
	c := Counters{m: map[string]int{}}
	var wg sync.WaitGroup
	for range 100 {
		wg.Go(func() { c.Inc("visits") })
	}
	wg.Wait()
	fmt.Println(c.m["visits"]) // 100
}
```

`sync.RWMutex` helps when reads dominate. `sync.Map` is optimized for two specific cases: keys written once and read many times, or goroutines working on disjoint sets of keys. Otherwise, a map + mutex is usually faster and clearer.

## Composite keys

A comparable struct is the ideal key for several dimensions; avoid concatenating strings:

```go
package main

import "fmt"

type pos struct{ r, c int }

func main() {
	board := map[pos]string{{0, 0}: "X", {1, 1}: "O"}
	fmt.Println(board[pos{1, 1}])
}
```

## Summary

- Maps are references; `maps.Clone` for copies.
- Elements aren't addressable: write back or store pointers.
- `map[T]struct{}` for sets.
- `maps.Keys` gives an iterator; `slices.Sorted` sorts it.
- Concurrent access with writes needs a mutex (or `sync.Map` in special cases).
