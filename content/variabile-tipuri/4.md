# Variabile, tipuri și constante — Expert

Cum lucrează compilatorul și runtime-ul cu variabilele și tipurile: reprezentarea constantelor în compilator, ordinea de inițializare, layout-ul în memorie, descriptorii de tip din binar și valorile de dimensiune zero.

## Cum reprezintă compilatorul constantele

Precizia „arbitrară” a constantelor nu e o figură de stil: compilatorul folosește pachetul `go/constant`, construit peste `math/big`. Întregii sunt `big.Int`, iar fracțiile sunt păstrate ca **numere raționale exacte** (`big.Rat`) cât timp e posibil, cu `big.Float` doar ca rezervă. Poți folosi același pachet direct:

```go
package main

import (
	"fmt"
	"go/constant"
	"go/token"
)

func main() {
	x := constant.Shift(constant.MakeInt64(1), token.SHL, 100) // 1 << 100
	fmt.Println(x, constant.BitLen(x))                         // 1267650600228229401496703205376 101

	treime := constant.BinaryOp(constant.MakeInt64(1), token.QUO, constant.MakeInt64(3))
	inapoi := constant.BinaryOp(treime, token.MUL, constant.MakeInt64(3))
	fmt.Println(constant.Compare(inapoi, token.EQL, constant.MakeInt64(1))) // true: aritmetică exactă
}
```

Specificația cere ca implementările să reprezinte întregii constanți cu cel puțin 256 de biți și valorile în virgulă mobilă cu o mantisă de cel puțin 256 de biți; compilatorul `gc` merge mult peste această limită. Abia la **conversia** într-un tip concret valoarea e verificată și rotunjită — de aici erorile de tipul `constant 300 overflows uint8`.

## Ordinea de inițializare

Variabilele de la nivel de pachet sunt inițializate **în ordinea dependențelor**, nu neapărat în ordinea din fișier. Abia după ele rulează funcțiile `init()`, în ordinea în care apar (fișierele sunt date compilatorului sortate după nume de comanda `go`):

```go
package main

import "fmt"

var (
	a = b + 1 // depinde de b, deci b se inițializează primul
	b = f()
)

func f() int {
	fmt.Println("inițializez b")
	return 41
}

func init() {
	fmt.Println("init: a =", a)
}

func main() {
	fmt.Println("main")
}
```

Pachetele importate sunt inițializate complet înaintea pachetului care le importă. Ciclurile de inițializare sunt erori de compilare.

## Cum arată valorile în memorie

Valorile au dimensiune și aliniere fixe. Câmpurile unei structuri sunt aliniate, iar compilatorul adaugă *padding* între ele; ordinea câmpurilor contează:

```go
package main

import (
	"fmt"
	"unsafe"
)

type Risipitor struct {
	a bool  // 1 octet + 7 padding
	b int64 // 8
	c bool  // 1 octet + 7 padding
}

type Compact struct {
	b int64 // 8
	a bool  // 1
	c bool  // 1 + 6 padding
}

func main() {
	fmt.Println(unsafe.Sizeof(Risipitor{}), unsafe.Sizeof(Compact{})) // 24 16
	fmt.Println(unsafe.Sizeof(""), unsafe.Sizeof([]int{}))            // 16 24
}
```

Un `string` e un antet de 2 cuvinte (pointer + lungime); un slice e de 3 cuvinte (pointer, lungime, capacitate). Analizorul `fieldalignment` (din `golang.org/x/tools`) sugerează ordinea optimă a câmpurilor.

## Descriptorii de tip din binar

Fiecare tip folosit la rulare (prin interfețe, reflection, alocare pe heap) are în binar un **descriptor** (`internal/abi.Type`), generat de compilator:

```go,ignore
type Type struct {
	Size_       uintptr // dimensiunea în octeți
	PtrBytes    uintptr // prefixul care poate conține pointeri (restul nu e scanat de GC)
	Hash        uint32  // hash-ul tipului, folosit de type switch și de map-uri
	TFlag       TFlag
	Align_      uint8
	FieldAlign_ uint8
	Kind_       Kind
	Equal       func(unsafe.Pointer, unsafe.Pointer) bool // nil dacă tipul nu e comparabil
	GCData      *byte // harta pointerilor, pentru GC
	Str         NameOff
	PtrToThis   TypeOff
}
```

`reflect.TypeOf(x)` întoarce exact acest descriptor, privit prin interfața `reflect.Type`:

```go
package main

import (
	"fmt"
	"reflect"
)

type Punct struct {
	X, Y int32
	Nume string
}

func main() {
	t := reflect.TypeOf(Punct{})
	fmt.Println(t.Size(), t.Align(), t.Kind(), t.Comparable()) // 24 8 struct true
	for i := range t.NumField() {
		f := t.Field(i)
		fmt.Printf("%-4s offset=%-2d size=%d\n", f.Name, f.Offset, f.Type.Size())
	}
}
```

`PtrBytes` și `GCData` explică de ce structurile fără pointeri sunt ieftine pentru GC: GC-ul citește harta și sare peste tot ce nu poate conține pointeri. Funcția `Equal` e cea folosită de `==` pe interfețe și de map-uri; pentru tipurile fără padding și fără câmpuri speciale (float-uri, stringuri, interfețe), ea se reduce la o comparație de memorie (`memequal`).

## Valorile de dimensiune zero

Toate alocările de dimensiune zero (`new(struct{})`, `make([]int, 0)` pe heap, `[0]int{}`) primesc aceeași adresă: variabila globală `runtime.zerobase`. Nu se alocă nimic. Consecința: specificația spune explicit că doi pointeri la variabile distincte de dimensiune zero **pot sau nu** să fie egali.

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	a, b := new(struct{}), new(struct{})
	fmt.Println(unsafe.Sizeof(*a)) // 0
	fmt.Println(a == b)            // nespecificat: nu te baza pe rezultat
}
```

De aceea `struct{}` e ideal ca valoare în seturi și ca semnal pe channels: zero octeți, zero alocări.

## Pe scurt

- Compilatorul calculează constantele exact, cu `go/constant` (peste `math/big`).
- Inițializarea pachetului urmează dependențele, apoi `init()`.
- Ordinea câmpurilor schimbă dimensiunea structurilor (padding, aliniere).
- Fiecare tip are un descriptor în binar: dimensiune, harta pointerilor, hash, funcție de egalitate.
- Valorile de dimensiune zero nu alocă și pot împărți aceeași adresă.
