# Arrays and slices — Practitioner

Almost every slice bug has the same cause: several slices **share the same array**. At this level we see when that happens, how to control it, and what common operations the `slices` package offers.

## Slices that share memory

A sub-slice doesn't copy the elements. A write through one is visible in the other:

```go
package main

import "fmt"

func main() {
	original := []int{1, 2, 3, 4, 5}
	middle := original[1:4] // [2 3 4], the same array
	middle[0] = 99
	fmt.Println(original) // [1 99 3 4 5]
}
```

## The `append` trap on a sub-slice

If the sub-slice has spare capacity, `append` writes **into the shared array**, over the original slice's elements:

```go
package main

import "fmt"

func main() {
	s := []int{1, 2, 3, 4}
	first := s[:2]            // len 2, cap 4
	first = append(first, 99) // fits: overwrites s[2]
	fmt.Println(s)            // [1 2 99 4]
}
```

The **full slice expression** `s[a:b:c]` limits the capacity to `c-a`. A later `append` is forced to allocate a new array:

```go
package main

import "fmt"

func main() {
	s := []int{1, 2, 3, 4}
	first := s[:2:2]          // len 2, cap 2
	first = append(first, 99) // doesn't fit: new array
	fmt.Println(s, first)     // [1 2 3 4] [1 2 99]
}
```

When a function returns a sub-slice of an internal structure, `s[a:b:b]` or `slices.Clone` protects your data from the caller's `append`s.

## Preallocation

If you know (or can estimate) how many elements there will be, allocate up front. You avoid repeated reallocations and copies:

```go
package main

import (
	"fmt"
	"strings"
)

func upper(words []string) []string {
	res := make([]string, 0, len(words)) // a single allocation
	for _, w := range words {
		res = append(res, strings.ToUpper(w))
	}
	return res
}

func main() {
	fmt.Println(upper([]string{"go", "is", "fast"}))
}
```

Watch out for `make([]T, n)` vs `make([]T, 0, n)`: the first already has `n` zero elements, and `append` adds **after** them.

## nil vs. empty slice

A `nil` slice and an empty one (`[]int{}`) both have length 0 and behave the same with `len`, `range` and `append`. The difference shows up when comparing with `nil` and when serializing:

```go
package main

import (
	"encoding/json"
	"fmt"
)

func main() {
	var a []int                     // nil
	b := []int{}                    // empty, non-nil
	fmt.Println(a == nil, b == nil) // true false

	ja, _ := json.Marshal(a)
	jb, _ := json.Marshal(b)
	fmt.Println(string(ja), string(jb)) // null []
}
```

For checks, use `len(s) == 0`, not `s == nil`.

## Common operations with `slices`

```go
package main

import (
	"fmt"
	"slices"
)

func main() {
	s := []int{3, 1, 4, 1, 5, 9, 2, 6}

	s = slices.Delete(s, 1, 3) // removes indices 1 and 2
	fmt.Println(s)             // [3 1 5 9 2 6]

	s = slices.Insert(s, 0, 100)
	fmt.Println(s) // [100 3 1 5 9 2 6]

	s = slices.DeleteFunc(s, func(x int) bool { return x%2 == 0 })
	fmt.Println(s) // [3 1 5 9]

	slices.Sort(s)
	i, found := slices.BinarySearch(s, 5)
	fmt.Println(s, i, found) // [1 3 5 9] 2 true

	d := []int{1, 1, 2, 2, 2, 3}
	fmt.Println(slices.Compact(d)) // [1 2 3]: removes consecutive duplicates
	fmt.Println(slices.Equal([]int{1, 2}, []int{1, 2}))
}
```

## Sorting by your own criteria

`slices.SortFunc` takes a comparison function returning a negative number, zero or a positive number; `cmp.Compare` and `cmp.Or` (for several criteria) make it easy to write:

```go
package main

import (
	"cmp"
	"fmt"
	"slices"
)

type Employee struct {
	Name string
	Age  int
}

func main() {
	e := []Employee{{"Ion", 30}, {"Ana", 25}, {"Dan", 30}}
	slices.SortFunc(e, func(x, y Employee) int {
		return cmp.Or(
			cmp.Compare(y.Age, x.Age),   // age, descending
			cmp.Compare(x.Name, y.Name), // then name, ascending
		)
	})
	fmt.Println(e) // [{Dan 30} {Ion 30} {Ana 25}]
}
```

`slices.SortStableFunc` keeps the order of equal elements.

## Filtering in place

A classic pattern that reuses the existing array, with no allocation:

```go
package main

import "fmt"

func main() {
	s := []int{1, 2, 3, 4, 5, 6}
	even := s[:0] // same memory, length 0
	for _, x := range s {
		if x%2 == 0 {
			even = append(even, x)
		}
	}
	fmt.Println(even) // [2 4 6]
}
```

After filtering, the original `s` must not be used anymore: its contents have been overwritten.

## Arrays are values

Unlike slices, arrays are **copied** on assignment and in calls. They're also comparable with `==`, so they can be map keys:

```go
package main

import "fmt"

func main() {
	a := [2]int{1, 2}
	b := a // a full copy
	b[0] = 100
	fmt.Println(a, b, a == [2]int{1, 2}) // [1 2] [100 2] true

	visited := map[[2]int]bool{{0, 0}: true}
	fmt.Println(visited[[2]int{0, 0}])
}
```

## Summary

- Sub-slices share the array; `append` on them can overwrite data.
- `s[a:b:c]` or `slices.Clone` isolates a sub-slice.
- Preallocate with `make([]T, 0, n)`.
- Check for empty with `len(s) == 0`; `nil` and `[]` differ in JSON.
- The `slices` package + `cmp` cover sorting, searching and deleting.
