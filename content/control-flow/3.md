# Control flow — Avansat

Semantica exactă a instrucțiunilor de control: ce face `range` cu expresia pe care o parcurge, de ce ordinea în maps e aleatoare, cum decodează stringurile, ce se întâmplă cu `defer` în bucle și ce garantează (și ce nu) specificația despre ordinea de evaluare.

## `range` evaluează expresia o singură dată

Expresia de după `range` e evaluată **o singură dată**, înainte de prima iterație. Pentru slices, lungimea e fixată atunci; adăugările din buclă nu prelungesc parcurgerea:

```go
package main

import "fmt"

func main() {
	s := []int{1, 2, 3}
	for i, v := range s {
		if i == 0 {
			s = append(s, 99) // s indică acum alt array, mai lung
		}
		fmt.Print(v, " ")
	}
	fmt.Println("\nlen:", len(s)) // bucla a făcut 3 pași, dar len e 4
}
```

Pentru un **array** (nu slice), `range` parcurge o **copie** a lui. Modificările din buclă nu se văd în valorile primite:

```go
package main

import "fmt"

func main() {
	arr := [3]int{1, 2, 3}
	for i, v := range arr { // copie a array-ului
		arr[2] = 100
		fmt.Print(i, ":", v, " ") // 0:1 1:2 2:3
	}
	fmt.Println()
	for i, v := range &arr { // pointer: fără copie
		arr[2] = 200
		fmt.Print(i, ":", v, " ") // 0:1 1:2 2:200
	}
	fmt.Println()
}
```

Valoarea `v` e întotdeauna o copie a elementului. Pentru a modifica elementele unui slice de structuri, folosește indexul: `s[i].Camp = x`. Pentru array-uri mari de structuri, `for i := range s` evită și copierea fiecărui element.

## Ordinea în maps e aleatoare intenționat

Runtime-ul alege un punct de start aleatoriu la fiecare `range` peste un map, ca nimeni să nu depindă de o ordine. Ștergerea unei chei în timpul parcurgerii e sigură; o cheie adăugată în timpul parcurgerii **poate** să apară sau nu.

```go
package main

import (
	"fmt"
	"maps"
	"slices"
)

func main() {
	m := map[string]int{"c": 3, "a": 1, "b": 2}
	for _, k := range slices.Sorted(maps.Keys(m)) { // ordine stabilă
		fmt.Println(k, m[k])
	}
}
```

## `range` peste string decodează UTF-8

Pașii nu sunt de câte un octet, ci de câte un caracter. Octeții invalizi produc `U+FFFD` și avansează cu un singur octet:

```go
package main

import "fmt"

func main() {
	for i, r := range "aș\xffb" {
		fmt.Printf("%d:%q ", i, r) // 0:'a' 1:'ș' 3:'�' 4:'b'
	}
	fmt.Println()
}
```

## `defer` în bucle

`defer` rulează la ieșirea din **funcție**, nu din iterație. Într-o buclă care deschide fișiere, toate rămân deschise până la final:

```go,ignore
for _, nume := range fisiere {
	f, err := os.Open(nume)
	if err != nil {
		return err
	}
	defer f.Close() // se acumulează: toate se închid abia la return
	// ...
}
```

Soluția e să muți corpul buclei într-o funcție separată, unde `defer` rulează la fiecare apel.

## Ordinea de evaluare

Specificația garantează că **apelurile de funcții, apelurile de metode, operațiile de primire de pe channels și operatorii logici** dintr-o expresie sunt evaluate de la stânga la dreapta. Pentru **restul** operanzilor (variabile, indexări, câmpuri), ordinea față de apeluri **nu e specificată**:

```go
package main

import "fmt"

func main() {
	x := 1
	inc := func() int { x++; return x }

	// inc() e apelată înaintea lui fmt.Println, dar dacă x (al doilea argument)
	// e citit înainte sau după apel nu e specificat de limbaj
	fmt.Println(inc(), x) // 2 1 sau 2 2, în funcție de compilator
}
```

Regula practică: nu scrie expresii în care un apel modifică o variabilă citită în **aceeași** expresie. Desparte-le în instrucțiuni separate.

Atribuirile multiple au două faze bine definite: întâi sunt evaluați **toți** operanzii din stânga (indexuri, dereferențieri) și toate expresiile din dreapta, apoi atribuirile se fac de la stânga la dreapta. De aceea interschimbarea e sigură:

```go
package main

import "fmt"

func main() {
	a, b := 1, 2
	a, b = b, a // dreapta e evaluată complet înainte de orice atribuire
	fmt.Println(a, b)

	s := []int{10, 20, 30}
	i := 0
	i, s[i] = 1, 99 // s[i] folosește i dinainte de atribuire: s[0] = 99
	fmt.Println(i, s)
}
```

Operatorii `&&` și `||` sunt evaluați **leneș**: operandul din dreapta rulează doar dacă e nevoie, ceea ce face sigure gărzi ca `p != nil && p.X > 0`.

## Pe scurt

- `range` evaluează expresia o dată; array-urile sunt copiate, slices nu.
- Ordinea în maps e aleatoare intenționat; sortează cheile când contează.
- `range` peste string decodează UTF-8 și înlocuiește octeții invalizi cu `U+FFFD`.
- `defer` aparține funcției, nu iterației.
- Doar apelurile, primirile de pe channels și operatorii logici au ordine garantată; nu amesteca apeluri cu efecte și citiri în aceeași expresie.
