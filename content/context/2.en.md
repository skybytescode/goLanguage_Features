# Context — Practitioner

Using context correctly in a real application: propagation through layers, values in the context (and when not to use them), cancellation causes, `AfterFunc`, `WithoutCancel`, and how to write functions that respect cancellation.

## Propagation through layers

The context comes from the top (an HTTP handler, `main`, a queue consumer) and passes through **every** function that may block or take time. Each layer can shorten the deadline, but can't extend it:

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func queryDB(ctx context.Context) error {
	// the data layer imposes its own, shorter limit
	ctx, cancel := context.WithTimeout(ctx, 30*time.Millisecond)
	defer cancel()
	select {
	case <-time.After(100 * time.Millisecond):
		return nil
	case <-ctx.Done():
		return fmt.Errorf("query: %w", ctx.Err())
	}
}

func service(ctx context.Context) error {
	if err := queryDB(ctx); err != nil {
		return fmt.Errorf("service: %w", err)
	}
	return nil
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), time.Second)
	defer cancel()
	err := service(ctx)
	fmt.Println(err)
	fmt.Println(err != nil && ctx.Err() == nil) // true: only the bottom layer timed out
}
```

The effective deadline is always the **earliest** of the parent's and the child's.

## Write functions that respect cancellation

Cancellation is **cooperative**: the context doesn't stop anything by itself, it just closes a channel. Your code must check it:

- in long loops, with `ctx.Err()` or a `select` with `default`;
- at every wait (channel, timer), in a `select` with `<-ctx.Done()`;
- by passing it to functions that accept it.

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func processAll(ctx context.Context, items []int) (int, error) {
	done := 0
	for _, it := range items {
		if err := ctx.Err(); err != nil { // a cheap check on every step
			return done, err
		}
		time.Sleep(time.Duration(it) * time.Millisecond)
		done++
	}
	return done, nil
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 25*time.Millisecond)
	defer cancel()
	n, err := processAll(ctx, []int{10, 10, 10, 10, 10})
	fmt.Println(n, err) // 2 or 3, context deadline exceeded
}
```

## Values in the context

`context.WithValue` attaches a value. The key must be of an **unexported type**, so packages can't collide:

```go
package main

import (
	"context"
	"fmt"
)

type ctxKey int

const requestIDKey ctxKey = 0

func WithRequestID(ctx context.Context, id string) context.Context {
	return context.WithValue(ctx, requestIDKey, id)
}

func RequestID(ctx context.Context) (string, bool) {
	id, ok := ctx.Value(requestIDKey).(string)
	return id, ok
}

func main() {
	ctx := WithRequestID(context.Background(), "req-42")
	if id, ok := RequestID(ctx); ok {
		fmt.Println("processing request", id)
	}
}
```

What **to** put in a context: request-scoped data that crosses API boundaries — the request ID, tracing information, the authenticated user's identity.

What **not** to put: optional function parameters, database connections, loggers, configuration. These make dependencies invisible; pass them explicitly.

## The cancellation cause (Go 1.20+)

`ctx.Err()` only says *that* it was canceled. `WithCancelCause` and `WithTimeoutCause` also keep *why*:

```go
package main

import (
	"context"
	"errors"
	"fmt"
)

var ErrClientGone = errors.New("the client closed the connection")

func main() {
	ctx, cancel := context.WithCancelCause(context.Background())
	cancel(ErrClientGone)

	fmt.Println(ctx.Err())          // context canceled
	fmt.Println(context.Cause(ctx)) // the client closed the connection
}
```

## `AfterFunc`, `WithoutCancel`, `WithDeadline`

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithCancel(context.Background())

	// AfterFunc (Go 1.21): runs a function on cancellation, with no waiting goroutine
	stop := context.AfterFunc(ctx, func() {
		fmt.Println("cleanup after cancellation")
	})
	defer stop()

	// WithoutCancel (Go 1.21): keeps the values, but not the cancellation
	// useful for work that must continue after the response (auditing, metrics)
	detached := context.WithoutCancel(ctx)

	cancel()
	time.Sleep(10 * time.Millisecond)
	fmt.Println(ctx.Err(), detached.Err()) // context canceled <nil>

	// WithDeadline: like WithTimeout, but with an absolute moment
	dl, cancelDL := context.WithDeadline(context.Background(), time.Now().Add(time.Hour))
	defer cancelDL()
	d, _ := dl.Deadline()
	fmt.Println(time.Until(d).Round(time.Hour))
}
```

## Rules

1. The context is the **first parameter**, named `ctx`; don't store it in a struct (exceptions: types that represent an operation themselves, like `http.Request`).
2. Don't pass a `nil` context; use `context.TODO()`.
3. **Always** call the `cancel` function (`go vet` checks this with the `lostcancel` analyzer).
4. A context can be used from several goroutines at once.
5. Context values are for request data, not dependencies.

## Summary

- Each layer can shorten the deadline, never extend it.
- Cancellation is cooperative: check `ctx.Err()` / `ctx.Done()`.
- `WithValue` with unexported key types, only for request data.
- `WithCancelCause` + `context.Cause` explain why it was canceled.
- `AfterFunc` for cleanup, `WithoutCancel` for detached work.
