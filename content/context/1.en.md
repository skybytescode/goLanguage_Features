# Context — Fundamentals

The `context` package solves a common problem: how do you tell an operation (and every goroutine it started) that it must stop — because the user closed the page, a time limit expired, or the program is shutting down.

## What a `context.Context` is

A `ctx` value passed from function to function, carrying:

- a **cancellation** signal (`ctx.Done()`, a channel that gets closed);
- optionally, a **deadline**;
- optionally, request-scoped **values** (for example a request ID).

The convention: the context is the function's **first parameter** and is named `ctx`.

```go,ignore
func FetchPage(ctx context.Context, url string) ([]byte, error)
```

## The starting context

`context.Background()` is the root: it's never canceled. You use it in `main`, in tests and when starting services. `context.TODO()` is identical, but marks places where you haven't decided which context to use yet.

## A time limit: `WithTimeout`

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func slowOperation(ctx context.Context) error {
	select {
	case <-time.After(200 * time.Millisecond): // the "work" takes 200ms
		return nil
	case <-ctx.Done(): // the context was canceled
		return ctx.Err()
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel() // releases the context's resources

	err := slowOperation(ctx)
	fmt.Println("result:", err) // context deadline exceeded
}
```

`WithTimeout` returns a new context and a `cancel` function. **Always call `cancel`**, usually with `defer`, even if the operation finishes before the timeout.

## Manual cancellation: `WithCancel`

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func worker(ctx context.Context, results chan<- int) {
	for i := 0; ; i++ {
		select {
		case <-ctx.Done():
			fmt.Println("worker stopping:", ctx.Err())
			close(results)
			return
		case results <- i:
			time.Sleep(10 * time.Millisecond)
		}
	}
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel() // calling it twice is harmless
	results := make(chan int)
	go worker(ctx, results)

	for v := range results {
		if v == 3 {
			cancel() // done, we don't need more
		}
	}
	fmt.Println("main finished")
}
```

## `ctx.Err()`

After cancellation, `ctx.Err()` gives the reason:

| Error | When |
|---|---|
| `context.Canceled` | `cancel()` was called |
| `context.DeadlineExceeded` | the time limit expired |
| `nil` | the context isn't canceled (yet) |

## Contexts form a tree

A context created from another is its **child**. Canceling the parent automatically cancels all its children; canceling a child doesn't affect the parent:

```go
package main

import (
	"context"
	"fmt"
)

func main() {
	parent, cancelParent := context.WithCancel(context.Background())
	child, cancelChild := context.WithCancel(parent)
	defer cancelChild()

	cancelParent()
	<-child.Done() // the child was canceled along with the parent
	fmt.Println("child:", child.Err())
}
```

## Context in the standard library

Many functions already take a context and stop on their own when it's canceled:

- `http.NewRequestWithContext(ctx, ...)` — an HTTP request;
- `r.Context()` — in an HTTP handler, the context is canceled when the client closes the connection;
- `db.QueryContext(ctx, ...)` — an SQL query;
- `exec.CommandContext(ctx, ...)` — an external process, killed on cancellation.

## Summary

- `ctx` is the first parameter and carries cancellation, a deadline and values.
- `context.Background()` is the root.
- `WithTimeout` and `WithCancel` return a `cancel`: always call it with `defer`.
- Listen to `<-ctx.Done()` in loops and long operations.
- Cancellation propagates from parent to children.
