# I/O: Reader și Writer — Practician

Puterea interfețelor `Reader`/`Writer` vine din **compunere**: adaptori care se înlănțuie ca piesele de Lego. Tot aici: buffering corect, implementarea propriului `Reader`, `io.Pipe`, sistemele de fișiere abstracte (`fs.FS`, `embed`) și `os.Root`.

## Adaptorii din `io`

```go
package main

import (
	"bytes"
	"crypto/sha256"
	"fmt"
	"io"
	"os"
	"strings"
)

func main() {
	sursa := strings.NewReader("date importante care trebuie copiate")

	// copiază cel mult 15 octeți
	limitat := io.LimitReader(sursa, 15)

	// tot ce trece prin TeeReader e scris și în hash
	h := sha256.New()
	tee := io.TeeReader(limitat, h)

	// scrie simultan pe ecran și într-un buffer
	var copie bytes.Buffer
	destinatie := io.MultiWriter(os.Stdout, &copie)

	n, err := io.Copy(destinatie, tee)
	fmt.Printf("\n%d octeți, err=%v, sha256=%x…\n", n, err, h.Sum(nil)[:4])
}
```

| Adaptor | Ce face |
|---|---|
| `io.Copy(dst, src)` | copiază până la EOF |
| `io.LimitReader(r, n)` | se oprește după `n` octeți |
| `io.TeeReader(r, w)` | ce citești din `r` e scris și în `w` |
| `io.MultiWriter(w1, w2)` | scrie în toți |
| `io.MultiReader(r1, r2)` | citește pe rând din fiecare |
| `io.SectionReader` | o fereastră dintr-un `ReaderAt` |
| `io.NopCloser(r)` | adaugă un `Close` care nu face nimic |

Un exemplu real: `gzip.NewReader(resp.Body)` → `io.LimitReader` → `json.NewDecoder`. Fiecare strat știe doar de interfață.

## Buffering: `bufio.Writer`

Fiecare `Write` pe un fișier e un apel de sistem. Pentru multe scrieri mici, un `bufio.Writer` le adună într-un buffer (implicit 4 KB) și scrie în bucăți mari. **Nu uita `Flush`**:

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	w := bufio.NewWriter(os.Stdout)
	defer w.Flush() // fără Flush, ultimele date rămân în buffer
	for i := range 5 {
		fmt.Fprintf(w, "linia %d\n", i)
	}
}
```

La fișiere, ordinea e: `Flush()` pe writer, apoi `Close()` pe fișier, verificând ambele erori.

## Implementarea unui `Reader`

Un `Reader` propriu trebuie doar să umple `p` și să întoarcă `io.EOF` la final:

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

// rot13Reader transformă textul pe măsură ce e citit.
type rot13Reader struct{ r io.Reader }

func (rr rot13Reader) Read(p []byte) (int, error) {
	n, err := rr.r.Read(p)
	for i := range p[:n] {
		c := p[i]
		switch {
		case c >= 'a' && c <= 'z':
			p[i] = 'a' + (c-'a'+13)%26
		case c >= 'A' && c <= 'Z':
			p[i] = 'A' + (c-'A'+13)%26
		}
	}
	return n, err
}

func main() {
	r := rot13Reader{strings.NewReader("Lbh penpxrq gur pbqr!")}
	b, _ := io.ReadAll(r)
	fmt.Println(string(b)) // You cracked the code!
}
```

Observă că octeții citiți (`n > 0`) sunt procesați **înainte** de a verifica eroarea: un `Read` poate întoarce date și `io.EOF` în același apel.

## `io.Pipe`: conectarea unui Writer la un Reader

Când o funcție vrea un `Writer` iar alta un `Reader`, `io.Pipe` le leagă, fără buffer intermediar. Scrierea blochează până când cineva citește:

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
)

func main() {
	pr, pw := io.Pipe()

	go func() {
		// producătorul scrie JSON direct în pipe
		err := json.NewEncoder(pw).Encode(map[string]int{"a": 1, "b": 2})
		pw.CloseWithError(err) // nil → EOF pentru cititor
	}()

	// consumatorul îl citește ca stream (de ex. corpul unei cereri HTTP)
	date, err := io.ReadAll(pr)
	fmt.Println(string(date), err)
}
```

## Sisteme de fișiere abstracte: `fs.FS`

Interfața `fs.FS` descrie un sistem de fișiere doar pentru citire. Codul scris pentru ea funcționează cu un director de pe disc (`os.DirFS`), cu fișiere încorporate în binar (`embed.FS`), cu o arhivă zip sau cu un sistem de fișiere în memorie, util în teste (`testing/fstest.MapFS`):

```go
package main

import (
	"fmt"
	"io/fs"
	"testing/fstest"
)

func numaraFisiere(fsys fs.FS) (int, error) {
	n := 0
	err := fs.WalkDir(fsys, ".", func(p string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if !d.IsDir() {
			n++
		}
		return nil
	})
	return n, err
}

func main() {
	fsys := fstest.MapFS{
		"a.txt":       {Data: []byte("a")},
		"dir/b.txt":   {Data: []byte("b")},
		"dir/c/d.txt": {Data: []byte("d")},
	}
	fmt.Println(numaraFisiere(fsys)) // 3 <nil>
}
```

## `os.Root`: acces limitat la un director (Go 1.24)

Când căile vin de la utilizator, `filepath.Join(baza, cale)` nu e sigur: `../../etc/passwd` sau o legătură simbolică pot ieși din director. `os.Root` garantează că nicio operație nu iese din rădăcină:

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	dir, _ := os.MkdirTemp("", "uploads")
	defer os.RemoveAll(dir)

	root, err := os.OpenRoot(dir)
	if err != nil {
		fmt.Println(err)
		return
	}
	defer root.Close()

	f, err := root.Create("ok.txt") // în interiorul dir
	fmt.Println(err)
	f.Close()

	_, err = root.Open("../../etc/passwd") // refuzat
	fmt.Println(err != nil)
}
```

## Pe scurt

- Compune `Reader`/`Writer` cu `io.Copy`, `LimitReader`, `TeeReader`, `MultiWriter`.
- `bufio.Writer` pentru scrieri mici; `Flush` înainte de `Close`.
- Un `Read` poate întoarce date și eroare simultan: procesează întâi datele.
- `io.Pipe` leagă un producător de tip `Writer` de un consumator de tip `Reader`.
- `fs.FS` + `embed` + `fstest.MapFS` pentru cod testabil; `os.Root` pentru căi nesigure.
