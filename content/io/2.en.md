# I/O: Reader and Writer — Practitioner

The power of the `Reader`/`Writer` interfaces comes from **composition**: adapters that chain like Lego pieces. Also here: proper buffering, implementing your own `Reader`, `io.Pipe`, abstract file systems (`fs.FS`, `embed`) and `os.Root`.

## The `io` adapters

```go
package main

import (
	"bytes"
	"crypto/sha256"
	"fmt"
	"io"
	"os"
	"strings"
)

func main() {
	src := strings.NewReader("important data that must be copied")

	// copy at most 15 bytes
	limited := io.LimitReader(src, 15)

	// everything passing through TeeReader is written to the hash too
	h := sha256.New()
	tee := io.TeeReader(limited, h)

	// write to the screen and to a buffer at the same time
	var cp bytes.Buffer
	dst := io.MultiWriter(os.Stdout, &cp)

	n, err := io.Copy(dst, tee)
	fmt.Printf("\n%d bytes, err=%v, sha256=%x…\n", n, err, h.Sum(nil)[:4])
}
```

| Adapter | What it does |
|---|---|
| `io.Copy(dst, src)` | copies until EOF |
| `io.LimitReader(r, n)` | stops after `n` bytes |
| `io.TeeReader(r, w)` | what you read from `r` is also written to `w` |
| `io.MultiWriter(w1, w2)` | writes to all of them |
| `io.MultiReader(r1, r2)` | reads from each in turn |
| `io.SectionReader` | a window into a `ReaderAt` |
| `io.NopCloser(r)` | adds a `Close` that does nothing |

A real example: `gzip.NewReader(resp.Body)` → `io.LimitReader` → `json.NewDecoder`. Each layer only knows the interface.

## Buffering: `bufio.Writer`

Every `Write` to a file is a system call. For many small writes, a `bufio.Writer` gathers them in a buffer (4 KB by default) and writes in large chunks. **Don't forget `Flush`**:

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	w := bufio.NewWriter(os.Stdout)
	defer w.Flush() // without Flush, the last data stays in the buffer
	for i := range 5 {
		fmt.Fprintf(w, "line %d\n", i)
	}
}
```

With files, the order is: `Flush()` on the writer, then `Close()` on the file, checking both errors.

## Implementing a `Reader`

Your own `Reader` only has to fill `p` and return `io.EOF` at the end:

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

// rot13Reader transforms text as it's read.
type rot13Reader struct{ r io.Reader }

func (rr rot13Reader) Read(p []byte) (int, error) {
	n, err := rr.r.Read(p)
	for i := range p[:n] {
		c := p[i]
		switch {
		case c >= 'a' && c <= 'z':
			p[i] = 'a' + (c-'a'+13)%26
		case c >= 'A' && c <= 'Z':
			p[i] = 'A' + (c-'A'+13)%26
		}
	}
	return n, err
}

func main() {
	r := rot13Reader{strings.NewReader("Lbh penpxrq gur pbqr!")}
	b, _ := io.ReadAll(r)
	fmt.Println(string(b)) // You cracked the code!
}
```

Notice that the bytes read (`n > 0`) are processed **before** checking the error: a `Read` can return data and `io.EOF` in the same call.

## `io.Pipe`: connecting a Writer to a Reader

When one function wants a `Writer` and another wants a `Reader`, `io.Pipe` connects them, with no intermediate buffer. A write blocks until someone reads:

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
)

func main() {
	pr, pw := io.Pipe()

	go func() {
		// the producer writes JSON straight into the pipe
		err := json.NewEncoder(pw).Encode(map[string]int{"a": 1, "b": 2})
		pw.CloseWithError(err) // nil → EOF for the reader
	}()

	// the consumer reads it as a stream (e.g. an HTTP request body)
	data, err := io.ReadAll(pr)
	fmt.Println(string(data), err)
}
```

## Abstract file systems: `fs.FS`

The `fs.FS` interface describes a read-only file system. Code written against it works with a directory on disk (`os.DirFS`), files embedded in the binary (`embed.FS`), a zip archive or an in-memory file system, handy in tests (`testing/fstest.MapFS`):

```go
package main

import (
	"fmt"
	"io/fs"
	"testing/fstest"
)

func countFiles(fsys fs.FS) (int, error) {
	n := 0
	err := fs.WalkDir(fsys, ".", func(p string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if !d.IsDir() {
			n++
		}
		return nil
	})
	return n, err
}

func main() {
	fsys := fstest.MapFS{
		"a.txt":       {Data: []byte("a")},
		"dir/b.txt":   {Data: []byte("b")},
		"dir/c/d.txt": {Data: []byte("d")},
	}
	fmt.Println(countFiles(fsys)) // 3 <nil>
}
```

## `embed`: files in the binary

```go,ignore
import "embed"

//go:embed templates/*.html static
var files embed.FS // implements fs.FS

//go:embed version.txt
var version string
```

The files are included at compile time; the program no longer depends on them at run time. This very site embeds its content that way.

## `os.Root`: access confined to a directory (Go 1.24)

When paths come from users, `filepath.Join(base, path)` isn't safe: `../../etc/passwd` or a symbolic link can escape the directory. `os.Root` guarantees no operation leaves the root:

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	dir, _ := os.MkdirTemp("", "uploads")
	defer os.RemoveAll(dir)

	root, err := os.OpenRoot(dir)
	if err != nil {
		fmt.Println(err)
		return
	}
	defer root.Close()

	f, err := root.Create("ok.txt") // inside dir
	fmt.Println(err)
	f.Close()

	_, err = root.Open("../../etc/passwd") // refused
	fmt.Println(err != nil)
}
```

## Summary

- Compose `Reader`/`Writer` with `io.Copy`, `LimitReader`, `TeeReader`, `MultiWriter`.
- `bufio.Writer` for small writes; `Flush` before `Close`.
- A `Read` can return data and an error at once: process the data first.
- `io.Pipe` connects a `Writer`-style producer to a `Reader`-style consumer.
- `fs.FS` + `embed` + `fstest.MapFS` for testable code; `os.Root` for untrusted paths.
