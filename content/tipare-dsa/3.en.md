# DSA patterns — Advanced

Trees and graphs. Three of the patterns here — tree traversals, DFS and BFS — are in the original list; **Union-Find** and **Topological Sort** were suggested in the comments, and they are the two graph tools that interview lists most often leave out. The common point: you visit every node and every edge a bounded number of times, so most solutions are O(V + E).

## How to represent a graph in Go

| Representation | Go type | When |
|---|---|---|
| Adjacency list | `[][]int` (nodes `0..n-1`) | almost always; O(V + E) memory |
| Adjacency list with keys | `map[string][]string` | nodes with names (words, courses) |
| Implicit grid | `[][]byte` + direction array | islands, mazes, oranges |
| Edge list | `[][2]int` | the input of Union-Find and Kruskal |
| Adjacency matrix | `[][]bool` | small, dense graphs; O(V²) memory |

## 12. Binary Tree Traversal

*Inorder, preorder, postorder, level order.* The first three are DFS on a tree and differ only in **when** you process the node relative to its children; the fourth is BFS.

**What each order is for:**

- **preorder** — copy or serialize a tree; the root comes first, so you can rebuild it;
- **inorder** — a BST in sorted order; "the k-th smallest element"; validating a BST;
- **postorder** — anything that needs the answer of the children first: height, diameter, deleting a tree;
- **level order** — "by level", "the right side view", the minimum depth.

```go
package main

import (
	"fmt"
	"iter"
)

type TreeNode struct {
	Val         int
	Left, Right *TreeNode
}

// inorder, recursive: the simplest form.
func inorder(n *TreeNode, visit func(int)) {
	if n == nil {
		return
	}
	inorder(n.Left, visit)
	visit(n.Val)
	inorder(n.Right, visit)
}

// inorderIterative (LeetCode 94) with an explicit stack: go left as far as
// possible, process, then move to the right subtree.
func inorderIterative(root *TreeNode) []int {
	var res []int
	var stack []*TreeNode
	for n := root; n != nil || len(stack) > 0; {
		for ; n != nil; n = n.Left {
			stack = append(stack, n)
		}
		n = stack[len(stack)-1]
		stack = stack[:len(stack)-1]
		res = append(res, n.Val)
		n = n.Right
	}
	return res
}

// levelOrder (LeetCode 102): BFS; the queue length at the start of a level
// is exactly the number of nodes on that level.
func levelOrder(root *TreeNode) [][]int {
	if root == nil {
		return nil
	}
	var res [][]int
	queue := []*TreeNode{root}
	for len(queue) > 0 {
		level := make([]int, 0, len(queue))
		for range len(queue) {
			n := queue[0]
			queue = queue[1:]
			level = append(level, n.Val)
			if n.Left != nil {
				queue = append(queue, n.Left)
			}
			if n.Right != nil {
				queue = append(queue, n.Right)
			}
		}
		res = append(res, level)
	}
	return res
}

// buildTree (LeetCode 105): preorder gives the root, its position in inorder
// splits the left subtree from the right one.
func buildTree(preorder, inorder []int) *TreeNode {
	pos := make(map[int]int, len(inorder)) // value → index in inorder
	for i, v := range inorder {
		pos[v] = i
	}
	next := 0 // the next root in preorder
	var build func(lo, hi int) *TreeNode
	build = func(lo, hi int) *TreeNode { // the subtree is inorder[lo:hi]
		if lo >= hi {
			return nil
		}
		root := &TreeNode{Val: preorder[next]}
		next++
		mid := pos[root.Val]
		root.Left = build(lo, mid)
		root.Right = build(mid+1, hi)
		return root
	}
	return build(0, len(inorder))
}

// All is an inorder iterator (Go 1.23+): it can be used with range and it
// stops as soon as the loop does a break.
func (n *TreeNode) All() iter.Seq[int] {
	return func(yield func(int) bool) {
		var walk func(*TreeNode) bool
		walk = func(n *TreeNode) bool {
			return n == nil || walk(n.Left) && yield(n.Val) && walk(n.Right)
		}
		walk(n)
	}
}

func main() {
	root := buildTree([]int{4, 2, 1, 3, 6, 5, 7}, []int{1, 2, 3, 4, 5, 6, 7})

	inorder(root, func(v int) { fmt.Print(v, " ") })
	fmt.Println()                       // 1 2 3 4 5 6 7
	fmt.Println(inorderIterative(root)) // [1 2 3 4 5 6 7]
	fmt.Println(levelOrder(root))       // [[4] [2 6] [1 3 5 7]]

	for v := range root.All() { // the 3rd smallest element
		if v == 3 {
			fmt.Println("found", v) // found 3
			break
		}
	}
}
```

> `queue = queue[1:]` is the simplest queue in Go. The slice "moves forward" over the backing array; `append` reallocates from time to time and the consumed part can be collected. For a queue that lives long, with many operations, a ring buffer avoids the copies.

**Complexity:** O(n) time; O(h) memory for DFS (h = the height), O(w) for BFS (w = the maximum width). **Practice:** [102. Binary Tree Level Order Traversal](https://leetcode.com/problems/binary-tree-level-order-traversal/) · [94. Binary Tree Inorder Traversal](https://leetcode.com/problems/binary-tree-inorder-traversal/) · [105. Construct Binary Tree from Preorder and Inorder Traversal](https://leetcode.com/problems/construct-binary-tree-from-preorder-and-inorder-traversal/)

## 13. Depth-First Search

*Go deep before you go wide.* From a node, you follow an edge to an unvisited neighbor, and so on, until you hit a dead end; then you return (backtrack) and try the next neighbor. Recursion gives you the stack for free.

**Signals:** connected regions, "number of islands / provinces", "does a path exist", cycle detection, cloning a graph, any problem on trees where the answer for a node depends on its subtrees.

```go
package main

import "fmt"

// numIslands (LeetCode 200). It marks visited cells by changing them to '0';
// if the input must stay intact, use a separate visited [][]bool.
func numIslands(grid [][]byte) int {
	rows, cols := len(grid), len(grid[0])
	var sink func(r, c int)
	sink = func(r, c int) {
		if r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] != '1' {
			return
		}
		grid[r][c] = '0'
		sink(r+1, c)
		sink(r-1, c)
		sink(r, c+1)
		sink(r, c-1)
	}
	count := 0
	for r := range rows {
		for c := range cols {
			if grid[r][c] == '1' {
				count++
				sink(r, c)
			}
		}
	}
	return count
}

type Node struct {
	Val       int
	Neighbors []*Node
}

// cloneGraph (LeetCode 133). The map is both "visited" and "old → copy";
// without it, a cycle would make the recursion infinite.
func cloneGraph(n *Node) *Node {
	copies := map[*Node]*Node{}
	var clone func(*Node) *Node
	clone = func(n *Node) *Node {
		if n == nil {
			return nil
		}
		if c, ok := copies[n]; ok {
			return c
		}
		c := &Node{Val: n.Val}
		copies[n] = c // before the neighbors: they may point back to n
		for _, nb := range n.Neighbors {
			c.Neighbors = append(c.Neighbors, clone(nb))
		}
		return c
	}
	return clone(n)
}

type TreeNode struct {
	Val         int
	Left, Right *TreeNode
}

// diameterOfBinaryTree (LeetCode 543): DFS in postorder. The function
// returns the height, and on the way it updates the longest path through
// every node (left height + right height).
func diameterOfBinaryTree(root *TreeNode) int {
	best := 0
	var height func(*TreeNode) int
	height = func(n *TreeNode) int {
		if n == nil {
			return 0
		}
		l, r := height(n.Left), height(n.Right)
		best = max(best, l+r)
		return 1 + max(l, r)
	}
	height(root)
	return best
}

func main() {
	grid := [][]byte{
		[]byte("11000"),
		[]byte("11000"),
		[]byte("00100"),
		[]byte("00011"),
	}
	fmt.Println(numIslands(grid)) // 3

	// the square 1-2-3-4-1
	n1, n2, n3, n4 := &Node{Val: 1}, &Node{Val: 2}, &Node{Val: 3}, &Node{Val: 4}
	n1.Neighbors = []*Node{n2, n4}
	n2.Neighbors = []*Node{n1, n3}
	n3.Neighbors = []*Node{n2, n4}
	n4.Neighbors = []*Node{n1, n3}
	c := cloneGraph(n1)
	fmt.Println(c != n1, c.Val, c.Neighbors[0].Val, c.Neighbors[1].Val) // true 1 2 4
	fmt.Println(c.Neighbors[0].Neighbors[0] == c)                       // true: 2 points back to the copy of 1

	root := &TreeNode{1, &TreeNode{2, &TreeNode{Val: 4}, &TreeNode{Val: 5}}, &TreeNode{Val: 3}}
	fmt.Println(diameterOfBinaryTree(root)) // 3 (4 → 2 → 1 → 3)
}
```

> Deep recursion is less risky in Go than in Java or Python: goroutine stacks start small and **grow** as needed, up to 1 GB by default on 64-bit systems. A DFS a million levels deep works, but it uses a lot of memory; an explicit stack (`[]int`) keeps it under control.

For cycle detection in a **directed** graph, a `visited` boolean is not enough: you need three states — not visited, *in progress* (on the current path) and done. Finding an "in progress" neighbor means a cycle. Topological sort (section 16) does the same thing differently.

**Complexity:** O(V + E); for a grid, O(rows·cols). **Practice:** [200. Number of Islands](https://leetcode.com/problems/number-of-islands/) · [133. Clone Graph](https://leetcode.com/problems/clone-graph/) · [543. Diameter of Binary Tree](https://leetcode.com/problems/diameter-of-binary-tree/)

## 14. Breadth-First Search

*Explore level by level.* A queue holds the "wave front": first all the nodes at distance 1, then all those at distance 2, and so on. That is why, in a graph where every edge costs the same, **BFS finds the shortest path** in number of steps — the first time it reaches a node is through the shortest path.

```go
package main

import "fmt"

// orangesRotting (LeetCode 994): 0 empty, 1 fresh, 2 rotten.
func orangesRotting(grid [][]int) int {
	type cell struct{ r, c int }
	var queue []cell
	fresh := 0
	for r, row := range grid {
		for c, v := range row {
			switch v {
			case 2:
				queue = append(queue, cell{r, c}) // all sources at once
			case 1:
				fresh++
			}
		}
	}
	dirs := [4]cell{{-1, 0}, {1, 0}, {0, -1}, {0, 1}}
	minutes := 0
	for len(queue) > 0 && fresh > 0 {
		minutes++
		for range len(queue) { // exactly one level
			cur := queue[0]
			queue = queue[1:]
			for _, d := range dirs {
				r, c := cur.r+d.r, cur.c+d.c
				if r >= 0 && r < len(grid) && c >= 0 && c < len(grid[0]) && grid[r][c] == 1 {
					grid[r][c] = 2 // mark it when you ENQUEUE it, not when you dequeue it
					fresh--
					queue = append(queue, cell{r, c})
				}
			}
		}
	}
	if fresh > 0 {
		return -1 // some oranges can never be reached
	}
	return minutes
}

// ladderLength (LeetCode 127): the graph is implicit; two words are
// neighbors if they differ by one letter. We generate the neighbors instead
// of comparing every pair of words.
func ladderLength(begin, end string, words []string) int {
	dict := map[string]bool{}
	for _, w := range words {
		dict[w] = true
	}
	if !dict[end] {
		return 0
	}
	queue := []string{begin}
	delete(dict, begin)
	for steps := 1; len(queue) > 0; steps++ {
		for range len(queue) {
			w := []byte(queue[0])
			queue = queue[1:]
			if string(w) == end {
				return steps
			}
			for i := range w {
				orig := w[i]
				for ch := byte('a'); ch <= 'z'; ch++ {
					w[i] = ch
					if s := string(w); dict[s] {
						delete(dict, s) // visited
						queue = append(queue, s)
					}
				}
				w[i] = orig
			}
		}
	}
	return 0
}

func main() {
	fmt.Println(orangesRotting([][]int{{2, 1, 1}, {1, 1, 0}, {0, 1, 1}})) // 4
	fmt.Println(orangesRotting([][]int{{2, 1, 1}, {0, 1, 1}, {1, 0, 1}})) // -1

	words := []string{"hot", "dot", "dog", "lot", "log", "cog"}
	fmt.Println(ladderLength("hit", "cog", words)) // 5: hit → hot → dot → dog → cog
}
```

> Mark a node as visited when you **put it in the queue**, not when you take it out. Otherwise the same node can be added many times by different neighbors, and on a grid the queue can grow exponentially.

*01 Matrix* (LeetCode 542) is the same idea as the oranges: put **all** the zeros in the queue at the start, and the BFS gives every cell its distance to the nearest zero. With edges of different costs, BFS is no longer enough: you need Dijkstra (a BFS with a heap instead of a queue).

**Complexity:** O(V + E). **Practice:** [127. Word Ladder](https://leetcode.com/problems/word-ladder/) · [994. Rotting Oranges](https://leetcode.com/problems/rotting-oranges/) · [542. 01 Matrix](https://leetcode.com/problems/01-matrix/)

## 15. Union-Find (Disjoint Set Union)

*"Are these two in the same group?" in almost O(1).* Every group is a tree, and the root is the representative of the group. `Find` climbs to the root; `Union` attaches one root under the other. Two optimizations make the trees almost flat: **union by size** (the small tree goes under the big one) and **path compression** (on the way up, nodes are moved closer to the root).

**Signals:** "connected components" when edges keep **arriving** (you cannot easily do it with DFS), "the redundant edge that closes a cycle", merging accounts/groups by a common element, Kruskal's minimum spanning tree.

```go
package main

import "fmt"

type UnionFind struct {
	parent, size []int
	count        int // the number of groups
}

func NewUnionFind(n int) *UnionFind {
	uf := &UnionFind{parent: make([]int, n), size: make([]int, n), count: n}
	for i := range n {
		uf.parent[i] = i
		uf.size[i] = 1
	}
	return uf
}

// Find returns the root, with "path halving": every node on the way is
// moved under its grandparent. Iterative, so there is no deep recursion.
func (uf *UnionFind) Find(x int) int {
	for uf.parent[x] != x {
		uf.parent[x] = uf.parent[uf.parent[x]]
		x = uf.parent[x]
	}
	return x
}

// Union merges the groups of a and b. It returns false if they were
// already in the same group: the edge (a, b) closes a cycle.
func (uf *UnionFind) Union(a, b int) bool {
	ra, rb := uf.Find(a), uf.Find(b)
	if ra == rb {
		return false
	}
	if uf.size[ra] < uf.size[rb] {
		ra, rb = rb, ra
	}
	uf.parent[rb] = ra // the smaller tree goes under the bigger one
	uf.size[ra] += uf.size[rb]
	uf.count--
	return true
}

// findCircleNum (LeetCode 547): the number of provinces in an adjacency matrix.
func findCircleNum(isConnected [][]int) int {
	uf := NewUnionFind(len(isConnected))
	for i := range isConnected {
		for j := i + 1; j < len(isConnected); j++ {
			if isConnected[i][j] == 1 {
				uf.Union(i, j)
			}
		}
	}
	return uf.count
}

// findRedundantConnection (LeetCode 684): the first edge that joins two
// nodes that are already connected. The nodes are numbered from 1.
func findRedundantConnection(edges [][2]int) [2]int {
	uf := NewUnionFind(len(edges) + 1)
	for _, e := range edges {
		if !uf.Union(e[0], e[1]) {
			return e
		}
	}
	return [2]int{}
}

func main() {
	uf := NewUnionFind(6)
	uf.Union(0, 1)
	uf.Union(0, 2)
	uf.Union(3, 4)
	fmt.Println(uf.count, uf.Find(2) == uf.Find(4)) // 3 false
	uf.Union(2, 4)
	fmt.Println(uf.count, uf.Find(2) == uf.Find(4)) // 2 true

	fmt.Println(findCircleNum([][]int{{1, 1, 0}, {1, 1, 0}, {0, 0, 1}}))   // 2
	fmt.Println(findRedundantConnection([][2]int{{1, 2}, {1, 3}, {2, 3}})) // [2 3]
}
```

With both optimizations, every operation costs O(α(n)), where α is the inverse Ackermann function — under 5 for any `n` that fits in memory. In practice: constant.

**Complexity:** ≈ O(1) per operation, O(n) memory. **Practice:** [547. Number of Provinces](https://leetcode.com/problems/number-of-provinces/) · [684. Redundant Connection](https://leetcode.com/problems/redundant-connection/) · [721. Accounts Merge](https://leetcode.com/problems/accounts-merge/)

## 16. Topological Sort

*An order in which every node comes after its dependencies.* It exists only in a **directed acyclic graph** (DAG). Kahn's algorithm counts, for every node, how many dependencies it still has (the in-degree); the nodes with 0 can be processed, and processing them decrements the counter of the nodes that depend on them.

**Signals:** prerequisites, dependencies, "build order", "can all the courses be finished?", a recipe that needs other recipes, the order of tasks in a pipeline.

The Go toolchain itself uses it: packages are compiled in a topological order of the import graph, and `import cycle not allowed` is exactly the case where that order does not exist.

```go
package main

import "fmt"

// findOrder (LeetCode 210): numCourses courses, prereq[i] = {course, needs}.
// It returns an order, or false if there is a cycle (LeetCode 207).
func findOrder(numCourses int, prereq [][2]int) ([]int, bool) {
	adj := make([][]int, numCourses)
	indeg := make([]int, numCourses)
	for _, p := range prereq {
		course, needs := p[0], p[1]
		adj[needs] = append(adj[needs], course) // needs → course
		indeg[course]++
	}
	var queue []int
	for c, d := range indeg {
		if d == 0 {
			queue = append(queue, c)
		}
	}
	order := make([]int, 0, numCourses)
	for len(queue) > 0 {
		c := queue[0]
		queue = queue[1:]
		order = append(order, c)
		for _, next := range adj[c] {
			indeg[next]--
			if indeg[next] == 0 { // all its prerequisites are done
				queue = append(queue, next)
			}
		}
	}
	// if a cycle exists, its nodes never reach in-degree 0
	return order, len(order) == numCourses
}

func main() {
	// 0=A, 1=B, 2=C, 3=D, 4=E as in the diagram
	edges := [][2]int{{1, 0}, {2, 0}, {3, 1}, {3, 2}, {4, 3}}
	fmt.Println(findOrder(5, edges)) // [0 1 2 3 4] true

	fmt.Println(findOrder(2, [][2]int{{0, 1}, {1, 0}})) // [] false: a cycle
}
```

The DFS alternative: run a DFS with three colors (section 13) and add every node to a list **after** all its descendants are done (postorder); the reversed list is a topological order. Kahn's version has an advantage: it naturally gives you the "levels" — what can be done in parallel at every step.

**Complexity:** O(V + E). **Practice:** [207. Course Schedule](https://leetcode.com/problems/course-schedule/) · [210. Course Schedule II](https://leetcode.com/problems/course-schedule-ii/) · [2115. Find All Possible Recipes from Given Supplies](https://leetcode.com/problems/find-all-possible-recipes-from-given-supplies/)

## Summary

- Traversals differ only in when the node is processed; postorder is for "the answer from the children", level order is BFS.
- DFS: connected regions, paths, cloning, cycles; recursion is cheap in Go, but it is not free.
- BFS: the shortest path in steps; mark when you enqueue; several sources can start at the same time.
- Union-Find: groups that merge over time, with union by size and path compression.
- Topological sort: dependencies in a DAG; Kahn's algorithm also detects cycles.
