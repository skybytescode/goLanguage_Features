# JSON and encoding — Expert

How `encoding/json` works under the hood: the scanner as a state machine, encoders built via reflection and cached, and where time and memory go.

## The scanner: a state machine

JSON validation is done by a `scanner`: a state machine that receives one byte at a time and returns a code (`scanBeginObject`, `scanObjectKey`, `scanContinue`, `scanError` …). Each state is a **function**; the scanner holds a pointer to the current state's function and a stack with the context (object or array) for nesting:

```go,ignore
type scanner struct {
	step       func(*scanner, byte) int // the current state
	parseState []int                    // the stack: parseObjectKey, parseObjectValue, parseArrayValue
	err        error
	bytes      int64
}

func stateBeginValue(s *scanner, c byte) int {
	switch c {
	case '{':
		s.step = stateBeginStringOrEmpty
		return s.pushParseState(c, parseObjectKey, scanBeginObject)
	case '"':
		s.step = stateInString
		return scanBeginLiteral
	// ...
	}
}
```

`json.Valid` runs only the scanner. `Unmarshal` runs it **once** over the whole input (validation), then decodes in a second pass, using the same scanner to skip quickly over values nobody wants (unknown fields). `json.Decoder` also uses the scanner to find the **end** of each value in the stream before decoding it.

Nesting depth is limited to 10,000 levels, so malicious input (`[[[[[…`) can't exhaust the stack.

## Reflection and the encoder cache

On the first `Marshal` of a type, the package inspects it through `reflect`: the fields, the tags, `MarshalJSON`/`MarshalText` methods, embedded fields. The result is a type-specific **encoding function**, kept in a global `sync.Map`. Later calls for the same type skip the analysis.

For structs, the analysis produces the list of fields with their names already escaped, the access index (including through embedded structs) and each field type's encoding function. When decoding, looking up a field by its JSON name uses a map, plus a case-insensitive comparison as a fallback.

## Where the time goes

- **Reflection** on every field (`reflect.Value.Field(i)`, interfaces): the main cost compared to generated code.
- **Allocations**: `Marshal` works in an internal buffer reused through `sync.Pool`, but the final result is always a new allocation; `Unmarshal` allocates strings for every string value and, for `any`, maps and slices.
- **Two-pass validation**: `Unmarshal` first scans the entire input to check it's valid JSON, then decodes it.
- **Custom methods**: `MarshalJSON` returns a `[]byte` the package must then **revalidate and compact**; a custom method can be slower than the default encoding.

When JSON is on the critical path, the options are: `json.Decoder` with concrete types (not `any`), reusing destination structs, code generators (easyjson, ffjson) or `encoding/json/v2`.

## Pointer methods and addressability

The encoder chosen for a type also depends on the **receiver** of its `MarshalJSON` method. If the method is defined on `*T`, it can only be called when the value is addressable. For this, `encoding/json` builds a conditional encoder (`condAddrEncoder`): at run time it checks whether the value has an address and picks between your method and the default encoding. The result is surprising:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Money int64

func (m *Money) MarshalJSON() ([]byte, error) { // pointer receiver
	return []byte(fmt.Sprintf(`"%d.%02d EUR"`, *m/100, *m%100)), nil
}

type Invoice struct{ Total Money }

func main() {
	inv := Invoice{Total: 1999}
	a, _ := json.Marshal(inv)  // inv is copied into an any: not addressable
	b, _ := json.Marshal(&inv) // through a pointer, the Total field is addressable
	fmt.Println(string(a))     // {"Total":1999}
	fmt.Println(string(b))     // {"Total":"19.99 EUR"}

	m, _ := json.Marshal(map[string]Money{"x": 5}) // map values aren't addressable
	fmt.Println(string(m))                         // {"x":5}
}
```

The practical rule: define `MarshalJSON` on a **value** receiver, so it's used however the value reaches the encoder. `UnmarshalJSON` stays on a pointer, since it must modify the value.

## Summary

- The scanner is a state machine with state functions and a nesting stack (max 10,000).
- `Unmarshal` validates the whole input first, then decodes.
- Encoders are built via reflection once per type and kept in a `sync.Map`.
- The cost comes from reflection, allocations and two-pass validation.
- A pointer-receiver `MarshalJSON` is ignored for non-addressable values; define it on a value receiver.
