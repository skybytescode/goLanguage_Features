# JSON and encoding — Practitioner

Fine control over serialization: `omitempty` vs. `omitzero`, `MarshalJSON`/`UnmarshalJSON` methods, streaming decoding with `Decoder`, strict validation, `json.RawMessage` for polymorphic JSON, and the other encodings in the standard library.

## `omitempty` and `omitzero` (Go 1.24)

`omitempty` omits the field if the value is "empty": `false`, `0`, `""`, `nil`, a slice/map of length 0. The problem: **structs** are never considered empty, so a zero `time.Time` always shows up. `omitzero` omits the field if it's the type's **zero value** (or if its `IsZero()` method returns `true`):

```go
package main

import (
	"encoding/json"
	"fmt"
	"time"
)

type Event struct {
	Name     string    `json:"name"`
	Notes    []string  `json:"notes,omitempty"`
	Created  time.Time `json:"created,omitempty"` // NOT omitted: a struct
	Modified time.Time `json:"modified,omitzero"`
	Priority int       `json:"priority,omitzero"`
}

func main() {
	b, _ := json.Marshal(Event{Name: "launch"})
	fmt.Println(string(b))
	// {"name":"launch","created":"0001-01-01T00:00:00Z"}
}
```

Careful: with `omitempty` or `omitzero`, a real `0` and "missing" become indistinguishable. If the difference matters (for a PATCH, say), use a pointer (`*int`).

## Your own types: `MarshalJSON` and `UnmarshalJSON`

A type can fully control its representation:

```go
package main

import (
	"encoding/json"
	"fmt"
	"strings"
)

type Color int

const (
	Red Color = iota
	Green
)

var names = []string{"red", "green"}

func (c Color) MarshalJSON() ([]byte, error) {
	return json.Marshal(names[c])
}

func (c *Color) UnmarshalJSON(b []byte) error {
	var s string
	if err := json.Unmarshal(b, &s); err != nil {
		return err
	}
	for i, n := range names {
		if strings.EqualFold(n, s) {
			*c = Color(i)
			return nil
		}
	}
	return fmt.Errorf("unknown color %q", s)
}

type Car struct {
	Model string `json:"model"`
	Color Color  `json:"color"`
}

func main() {
	b, _ := json.Marshal(Car{"Dacia", Green})
	fmt.Println(string(b)) // {"model":"Dacia","color":"green"}

	var c Car
	err := json.Unmarshal([]byte(`{"model":"Logan","color":"RED"}`), &c)
	fmt.Println(c, err)
}
```

`UnmarshalJSON` has a **pointer** receiver (it modifies the value); `MarshalJSON` usually has a value receiver, so it works for values, not just pointers. For types that are "text" (including map keys), implement `encoding.TextMarshaler`/`TextUnmarshaler` instead.

## Streaming decoding: `json.Decoder`

When data comes from an `io.Reader` (an HTTP request body, a file), `Decoder` reads straight from it, without loading everything into memory, and can process several consecutive values:

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"strings"
)

type Log struct {
	Level   string `json:"level"`
	Message string `json:"message"`
}

func main() {
	// JSON Lines: one object per line
	stream := strings.NewReader(`{"level":"info","message":"started"}
{"level":"error","message":"disk full"}
{"level":"info","message":"stopped"}`)

	dec := json.NewDecoder(stream)
	for {
		var l Log
		err := dec.Decode(&l)
		if err == io.EOF {
			break
		}
		if err != nil {
			fmt.Println(err)
			return
		}
		if l.Level == "error" {
			fmt.Println("!", l.Message)
		}
	}
}
```

## Strict validation

By default, unknown fields are silently ignored: a typo in a field name goes unnoticed. For APIs and configuration, be strict:

```go
package main

import (
	"encoding/json"
	"fmt"
	"strings"
)

type Config struct {
	Port int `json:"port"`
}

func main() {
	dec := json.NewDecoder(strings.NewReader(`{"port": 80, "prot": 443}`))
	dec.DisallowUnknownFields()
	var c Config
	fmt.Println(dec.Decode(&c)) // json: unknown field "prot"
}
```

Semantic validation (ports within range, required fields) is still up to you, after decoding.

## `json.RawMessage`: deferred decoding

For polymorphic messages, with a field that says the type of the rest, decode the "envelope" first and keep the variable part as raw bytes:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Envelope struct {
	Type string          `json:"type"`
	Data json.RawMessage `json:"data"`
}

type Payment struct{ Amount float64 }
type Delivery struct{ Address string }

func main() {
	messages := []string{
		`{"type":"payment","data":{"Amount":99.5}}`,
		`{"type":"delivery","data":{"Address":"1 Long St."}}`,
	}
	for _, m := range messages {
		var e Envelope
		json.Unmarshal([]byte(m), &e)
		switch e.Type {
		case "payment":
			var p Payment
			json.Unmarshal(e.Data, &p)
			fmt.Println("payment:", p.Amount)
		case "delivery":
			var d Delivery
			json.Unmarshal(e.Data, &d)
			fmt.Println("delivery to:", d.Address)
		}
	}
}
```

## Large numbers: `json.Number`

Decoded into `any`, numbers become `float64`, which loses precision above 2⁵³. Large IDs (from Twitter/X, for example) get corrupted. `dec.UseNumber()` keeps them as strings (`json.Number`), and the `,string` tag option serializes them as JSON strings.

## Other encodings in the standard library

| Package | For |
|---|---|
| `encoding/csv` | CSV files (with quotes, separators, multi-line records) |
| `encoding/xml` | XML, with similar `xml:"..."` tags |
| `encoding/base64`, `encoding/hex` | binary data as text |
| `encoding/binary` | numbers in binary form, with a chosen byte order |
| `encoding/gob` | Go↔Go serialization, efficient, typed |
| `encoding/pem` | PEM blocks (keys, certificates) |

## Summary

- `omitzero` (Go 1.24) also omits zero structs, like `time.Time{}`.
- `MarshalJSON`/`UnmarshalJSON` or `TextMarshaler` for custom representations.
- `json.Decoder` for streams; `DisallowUnknownFields` for strictness.
- `json.RawMessage` defers decoding of polymorphic parts.
- `UseNumber` or `,string` for large numbers.
