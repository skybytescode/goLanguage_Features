# JSON și encoding — Expert

Cum funcționează `encoding/json` pe dinăuntru: scanner-ul ca mașină de stări, encoderele construite prin reflection și păstrate în cache, și unde se duc timpul și memoria.

## Scanner-ul: o mașină de stări

Validarea JSON-ului se face cu un `scanner`: o mașină de stări care primește câte un octet și întoarce un cod (`scanBeginObject`, `scanObjectKey`, `scanContinue`, `scanError` …). Fiecare stare e o **funcție**; scanner-ul ține un pointer la funcția stării curente și o stivă cu contextul (obiect sau listă) pentru imbricare:

```go,ignore
type scanner struct {
	step       func(*scanner, byte) int // starea curentă
	parseState []int                    // stiva: parseObjectKey, parseObjectValue, parseArrayValue
	err        error
	bytes      int64
}

func stateBeginValue(s *scanner, c byte) int {
	switch c {
	case '{':
		s.step = stateBeginStringOrEmpty
		return s.pushParseState(c, parseObjectKey, scanBeginObject)
	case '"':
		s.step = stateInString
		return scanBeginLiteral
	// ...
	}
}
```

`json.Valid` rulează doar scanner-ul. `Unmarshal` îl rulează **o dată** pe tot input-ul (validare), apoi decodează într-o a doua trecere, folosind același scanner pentru a sări rapid peste valorile care nu interesează (câmpuri necunoscute). `json.Decoder` folosește scanner-ul și ca să găsească **sfârșitul** fiecărei valori din flux, înainte de a o decoda.

Adâncimea de imbricare e limitată la 10.000 de niveluri, ca un input rău intenționat (`[[[[[…`) să nu epuizeze stiva.

## Reflection și cache-ul de encodere

La primul `Marshal` al unui tip, pachetul îl inspectează prin `reflect`: câmpurile, tag-urile, metodele `MarshalJSON`/`MarshalText`, câmpurile încorporate. Rezultatul e o **funcție de encodare** specifică tipului, păstrată într-un `sync.Map` global. Apelurile următoare pentru același tip sar peste analiză.

Pentru structuri, analiza produce lista câmpurilor cu numele deja escapat, indexul de acces (inclusiv prin structuri încorporate) și funcția de encodare a tipului fiecărui câmp. La decodare, căutarea câmpului după numele din JSON folosește un map, plus o comparație case-insensitive ca fallback.

## Unde se duce timpul

- **Reflection** la fiecare câmp (`reflect.Value.Field(i)`, interfețe): costul principal față de cod generat.
- **Alocări**: `Marshal` lucrează într-un buffer intern refolosit prin `sync.Pool`, dar rezultatul final e mereu o alocare nouă; `Unmarshal` alocă stringuri pentru fiecare valoare string și, pentru `any`, map-uri și slice-uri.
- **Validarea în doi pași**: `Unmarshal` scanează întâi tot input-ul ca să verifice că e JSON valid, apoi îl decodează.
- **Metode proprii**: `MarshalJSON` întoarce `[]byte` care trebuie apoi **revalidat și compactat** de pachet; o metodă proprie poate fi mai lentă decât encodarea implicită.

Când JSON-ul e pe calea critică, opțiunile sunt: `json.Decoder` cu tipuri concrete (nu `any`), refolosirea structurilor de destinație, generatoare de cod (easyjson, ffjson) sau `encoding/json/v2`.

## Metodele pe pointer și adresabilitatea

Encoder-ul ales pentru un tip depinde și de **receptorul** metodei `MarshalJSON`. Dacă metoda e definită pe `*T`, ea poate fi apelată doar când valoarea e adresabilă. Pentru asta, `encoding/json` construiește un encoder condiționat (`condAddrEncoder`): la rulare verifică dacă valoarea are adresă și alege între metoda ta și encodarea implicită. Rezultatul surprinde:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Bani int64

func (b *Bani) MarshalJSON() ([]byte, error) { // receptor pointer
	return []byte(fmt.Sprintf(`"%d.%02d lei"`, *b/100, *b%100)), nil
}

type Factura struct{ Total Bani }

func main() {
	f := Factura{Total: 1999}
	a, _ := json.Marshal(f)  // f e copiat într-un any: nu e adresabil
	b, _ := json.Marshal(&f) // prin pointer, câmpul Total e adresabil
	fmt.Println(string(a))   // {"Total":1999}
	fmt.Println(string(b))   // {"Total":"19.99 lei"}

	m, _ := json.Marshal(map[string]Bani{"x": 5}) // valorile din map nu sunt adresabile
	fmt.Println(string(m))                        // {"x":5}
}
```

Regula practică: definește `MarshalJSON` pe receptor **valoare**, ca să fie folosită indiferent cum ajunge valoarea la encoder. `UnmarshalJSON` rămâne pe pointer, pentru că trebuie să modifice valoarea.

## Pe scurt

- Scanner-ul e o mașină de stări cu funcții-stare și o stivă de imbricare (max 10.000).
- `Unmarshal` validează întâi tot input-ul, apoi decodează.
- Encoderele sunt construite prin reflection o dată per tip și păstrate în `sync.Map`.
- Costul vine din reflection, alocări și validarea în doi pași.
- `MarshalJSON` pe receptor pointer e ignorată pentru valori neadresabile; definește-o pe receptor valoare.
