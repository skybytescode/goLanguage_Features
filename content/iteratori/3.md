# Range și iteratori — Avansat

De ce iteratorii Go sunt „push”, ce reguli trebuie să respecte un iterator (și ce se întâmplă când nu le respectă), iteratorii de unică folosință și cum raportezi erori dintr-un iterator.

## De ce push, nu pull

Majoritatea limbajelor folosesc iteratori **pull**: un obiect cu `Next()`, apelat de bucla `for`. Go a ales iteratori **push**: iteratorul e o funcție care apelează corpul buclei. Motivele:

- **Codul iteratorului e cod obișnuit.** Parcurgerea unui arbore e o funcție recursivă normală care apelează `yield`; în varianta pull ar trebui transformată într-o mașină de stări cu o stivă explicită.
- **Curățarea e naturală.** Un `defer` în iterator rulează la final sau la `break`; un iterator pull are nevoie de o metodă `Close` pe care apelantul o poate uita.
- **Performanța.** Un iterator push mic poate fi inlined complet împreună cu corpul buclei.

Pentru cazurile rare în care chiar ai nevoie de pull (doi iteratori parcurși în paralel), `iter.Pull` face conversia (vezi [Range și iteratori](../../iteratori/4/)).

## Verificări la rulare

Pentru că iteratorul e cod scris de oricine, compilatorul adaugă verificări în jurul lui `yield`. Încălcările dau panic cu mesaje explicite:

```go,panic
package main

import "fmt"

// Gresit ignoră rezultatul lui yield.
func Gresit(yield func(int) bool) {
	yield(1)
	yield(2) // apelat după ce bucla a făcut break
}

func main() {
	for x := range Gresit {
		fmt.Println(x)
		break
	}
	// panic: runtime error: range function continued iteration after function for loop body returned false
}
```

Alte situații detectate: apelarea lui `yield` după ce iteratorul s-a întors, sau un iterator care „înghite” un panic din corpul buclei și continuă.

## Iteratori de unică folosință

`iter.Seq` nu spune dacă iteratorul poate fi parcurs de mai multe ori. Cei construiți peste colecții (`slices.Values`, `maps.Keys`) pot fi reluați; cei construiți peste un flux (linii citite dintr-un `io.Reader`, rezultatele unei interogări SQL) de obicei nu. Convenția din biblioteca standard e să documentezi explicit iteratorii de unică folosință.

## Erori în iteratori

Un `iter.Seq[V]` nu are unde să întoarcă o eroare. Două tipare uzuale:

```go,ignore
// 1. Seq2 cu eroare pe fiecare element
func Randuri(db *sql.DB) iter.Seq2[Rand, error]

// 2. iterator + metodă Err(), ca bufio.Scanner
it := NouCititor(r)
for v := range it.All() { ... }
if err := it.Err(); err != nil { ... }
```

## Iteratori în API-uri

Când expui sau primești o secvență, alegerea dintre slice și iterator spune ceva despre contract:

| Întorci… | Când |
|---|---|
| `[]T` | rezultatul e mic, deja calculat, iar apelantul îl poate parcurge de mai multe ori sau îl poate modifica |
| `iter.Seq[T]` | rezultatul e mare, calculat leneș, infinit, sau construit dintr-o structură internă pe care nu vrei s-o expui |
| `iter.Seq2[T, error]` | fiecare element poate eșua (citire din fișiere, rețea, baze de date) |

| Primești… | Când |
|---|---|
| `[]T` | ai nevoie de `len`, de acces aleatoriu sau de mai multe parcurgeri |
| `iter.Seq[T]` | parcurgi o singură dată; apelantul poate trimite un slice (`slices.Values(s)`), un map, un generator |

Convențiile de denumire din biblioteca standard: `All()` pentru perechi index/cheie–valoare, `Values()` și `Keys()` pentru o singură componentă, `Backward()` pentru ordinea inversă. Funcțiile care consumă iteratori se numesc după rezultat (`Collect`, `Sorted`, `Insert`, `AppendSeq`).

## Pe scurt

- Push: iteratorul e cod obișnuit, curățarea e un `defer`, iar inlining-ul îl face rapid.
- Apelarea lui `yield` după `false` sau după întoarcere dă panic cu mesaj explicit.
- Documentează iteratorii de unică folosință (fluxuri, interogări).
- Erorile se raportează prin `Seq2[V, error]` sau printr-o metodă `Err()`.
- Întoarce `iter.Seq` pentru rezultate mari sau leneșe; primește `iter.Seq` când parcurgi o singură dată.
