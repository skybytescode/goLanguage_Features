# Tooling and profiling — Fundamentals

One of Go's greatest strengths is its built-in toolset: formatting, static analysis, documentation, testing, profiling and cross-compilation, all through the `go` command, with no configuration.

## `gofmt`: one style

```bash
go fmt ./...        # formats every file (runs gofmt -w)
gofmt -d .          # shows the differences without changing anything
```

Go has no debates about tabs vs. spaces or where braces go: `gofmt` decides, and the whole ecosystem uses it. Editors run it automatically on save.

## `go vet`: common mistakes

`go vet` finds code that compiles but is almost certainly wrong:

```go,ignore
fmt.Printf("%d\n", "text")         // vet: format %d has arg "text" of wrong type string
var mu sync.Mutex; m := mu         // vet: assignment copies lock value
ctx, _ := context.WithTimeout(...) // vet: the cancel function is not used
if x := 5; x == 5 || x == 5 {}     // vet: redundant or: x == 5 || x == 5
```

```bash
go vet ./...
```

`go test` automatically runs a subset of the `vet` checks before the tests.

## `go doc`: documentation in the terminal

```bash
go doc strings.Cut
go doc -all net/http.Client
go doc -http          # (Go 1.25) serves the documentation locally in a browser
```

The documentation comes straight from comments in the code. A comment that starts with the item's name, right above it, becomes its documentation:

```go,ignore
// Add returns the sum of a and b.
func Add(a, b int) int { return a + b }
```

For public packages, the same documentation appears on pkg.go.dev.

## Build, run, install

| Command | What it does |
|---|---|
| `go run .` | compiles into a temporary directory and runs |
| `go build -o app .` | creates the `app` executable |
| `go install ./cmd/tool` | installs into `$(go env GOPATH)/bin` |
| `go install golang.org/x/tools/cmd/stringer@latest` | installs an external tool |
| `go clean -cache` | empties the build cache |
| `go env` | shows the configuration (GOPATH, GOCACHE, GOOS...) |

## Cross-compilation

You build for another operating system or architecture by setting two variables. Nothing extra needs to be installed:

```bash
GOOS=windows GOARCH=amd64 go build -o app.exe .
GOOS=linux   GOARCH=arm64 go build -o app-arm .   # e.g. for a Raspberry Pi
GOOS=darwin  GOARCH=arm64 go build -o app-mac .
go tool dist list                                  # every supported combination
```

```go
package main

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Printf("built for %s/%s\n", runtime.GOOS, runtime.GOARCH)
}
```

## `gopls`: editor support

`gopls` is the official language server: completion, go-to-definition, safe renames, real-time errors, modernization suggestions. VS Code (the Go extension), GoLand, Neovim, Emacs and Zed use it.

## Additional linters

| Tool | For |
|---|---|
| `staticcheck` | hundreds of correctness, simplification and performance checks |
| `golangci-lint` | runs dozens of linters together, with one configuration |
| `govulncheck` | known vulnerabilities in the dependencies **you actually call** |

```bash
go install golang.org/x/vuln/cmd/govulncheck@latest
govulncheck ./...
```

## Your first profile

When a program is slow, don't guess: **measure**. The simplest route is a benchmark with a CPU profile:

```bash
go test -bench=. -cpuprofile=cpu.out
go tool pprof -http=:8080 cpu.out     # a flame graph in the browser
```

The Practitioner level goes into detail.

## Summary

- `go fmt` and `go vet` on every commit (or on save).
- `go doc` reads the documentation written in comments.
- `GOOS`/`GOARCH` for cross-compilation, with no extra tools.
- `gopls` in the editor; `staticcheck`/`golangci-lint` and `govulncheck` in CI.
- For performance: measure with `pprof`, don't guess.
