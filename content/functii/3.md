# Funcții și closures — Avansat

Semantica exactă a funcțiilor: ce se copiază la un apel, cum funcționează `return` cu rezultate cu nume, de ce argumentele variadice pot fi modificate de funcție, ce capturează un closure și de ce funcțiile nu se pot compara.

## Totul se transmite prin valoare

Go are o singură regulă: la apel, **fiecare argument e copiat**. Diferențele aparente vin din ce conține valoarea copiată:

| Tip | Ce se copiază | Efect vizibil la apelant |
|---|---|---|
| `int`, `struct`, array | toată valoarea | niciunul |
| pointer | adresa | modificările prin pointer |
| slice | antetul (pointer, len, cap) | modificarea elementelor, nu și `append` |
| map, channel, funcție | un pointer intern | toate modificările |
| interfață | perechea (tip, pointer la date) | depinde de valoarea dinăuntru |
| string | antetul (pointer, len) | niciunul: stringurile sunt imutabile |

Nu există „transmitere prin referință” ca în C++ (`int&`): orice efect la apelant trece printr-un pointer, explicit sau ascuns într-un tip.

## `return` în doi pași

Cu rezultate cu nume, `return expr` face două lucruri, în ordine: **atribuie** valorile rezultatelor, **apoi** rulează funcțiile amânate. De aceea un `defer` vede (și poate schimba) valoarea întoarsă:

```go
package main

import "fmt"

func numara() (n int) {
	defer func() { n *= 10 }() // rulează după ce return a pus 3 în n
	return 3
}

func faraNume() int {
	n := 3
	defer func() { n *= 10 }() // modifică variabila locală, nu rezultatul
	return n
}

func main() {
	fmt.Println(numara(), faraNume()) // 30 3
}
```

Fără nume, rezultatul e o variabilă ascunsă pe care `defer` nu o poate atinge.

## Argumentele variadice împart memoria

`f(s...)` nu copiază elementele: parametrul variadic **e** slice-ul transmis. Funcția poate deci modifica datele apelantului:

```go
package main

import "fmt"

func dubleaza(numere ...int) {
	for i := range numere {
		numere[i] *= 2
	}
}

func main() {
	s := []int{1, 2, 3}
	dubleaza(s...)
	fmt.Println(s) // [2 4 6]: aceeași memorie

	dubleaza(1, 2, 3) // aici se creează un slice nou, temporar
}
```

O funcție variadică ce păstrează argumentele (de exemplu într-un câmp) ar trebui să le copieze cu `slices.Clone`.

## Valorile funcție nu sunt comparabile

Două funcții nu pot fi comparate cu `==`; singura comparație permisă e cu `nil`. De aceea funcțiile nu pot fi chei de map.

```go,compile_fail
package main

func a() {}

func main() {
	f, g := a, a
	println(f == g) // eroare: func can only be compared to nil
}
```

## Closures capturează variabile, nu valori

Un closure nu face o copie a variabilelor din jur: le **împarte** cu funcția care l-a creat. Toate closure-urile create în același domeniu văd aceeași variabilă:

```go
package main

import "fmt"

func main() {
	contor := 0
	inc := func() { contor++ }
	afis := func() { fmt.Println("contor =", contor) }

	inc()
	inc()
	afis()      // contor = 2
	contor = 10 // modificarea directă e văzută și de closures
	afis()      // contor = 10
}
```

Singura excepție de la „o variabilă comună” sunt buclele `for`: din Go 1.22 fiecare iterație are propria variabilă, deci closure-urile create în iterații diferite văd variabile diferite (vezi [Control flow](../../control-flow/2/)).

## Pe scurt

- Totul se transmite prin valoare; efectele la apelant trec prin pointeri, explicit sau ascuns.
- `return` cu rezultate cu nume atribuie întâi, apoi rulează `defer`.
- `f(s...)` transmite chiar slice-ul apelantului.
- Closures împart variabilele cu funcția care le-a creat.
- Funcțiile se pot compara doar cu `nil`.
