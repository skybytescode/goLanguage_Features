# Functions and closures — Advanced

The exact semantics of functions: what gets copied on a call, how `return` works with named results, why variadic arguments can be modified by the function, what a closure captures and why functions can't be compared.

## Everything is passed by value

Go has one rule: on a call, **every argument is copied**. The apparent differences come from what the copied value contains:

| Type | What gets copied | Effect visible to the caller |
|---|---|---|
| `int`, `struct`, array | the whole value | none |
| pointer | the address | changes made through the pointer |
| slice | the header (pointer, len, cap) | changes to elements, but not `append` |
| map, channel, function | an internal pointer | every change |
| interface | the (type, data pointer) pair | depends on the value inside |
| string | the header (pointer, len) | none: strings are immutable |

There's no "pass by reference" as in C++ (`int&`): any effect on the caller goes through a pointer, explicit or hidden inside a type.

## `return` in two steps

With named results, `return expr` does two things, in order: it **assigns** the result values, **then** runs the deferred functions. That's why a `defer` sees (and can change) the returned value:

```go
package main

import "fmt"

func count() (n int) {
	defer func() { n *= 10 }() // runs after return has put 3 into n
	return 3
}

func unnamed() int {
	n := 3
	defer func() { n *= 10 }() // modifies the local variable, not the result
	return n
}

func main() {
	fmt.Println(count(), unnamed()) // 30 3
}
```

Without a name, the result is a hidden variable that `defer` can't touch.

## Variadic arguments share memory

`f(s...)` doesn't copy the elements: the variadic parameter **is** the slice passed in. The function can therefore modify the caller's data:

```go
package main

import "fmt"

func double(numbers ...int) {
	for i := range numbers {
		numbers[i] *= 2
	}
}

func main() {
	s := []int{1, 2, 3}
	double(s...)
	fmt.Println(s) // [2 4 6]: the same memory

	double(1, 2, 3) // here a new, temporary slice is created
}
```

A variadic function that keeps its arguments (in a field, say) should copy them with `slices.Clone`.

## Function values are not comparable

Two functions can't be compared with `==`; the only allowed comparison is with `nil`. That's why functions can't be map keys.

```go,compile_fail
package main

func a() {}

func main() {
	f, g := a, a
	println(f == g) // error: func can only be compared to nil
}
```

## Closures capture variables, not values

A closure doesn't copy the surrounding variables: it **shares** them with the function that created it. Every closure created in the same scope sees the same variable:

```go
package main

import "fmt"

func main() {
	counter := 0
	inc := func() { counter++ }
	show := func() { fmt.Println("counter =", counter) }

	inc()
	inc()
	show()       // counter = 2
	counter = 10 // a direct change is seen by the closures too
	show()       // counter = 10
}
```

The only exception to "one shared variable" are `for` loops: since Go 1.22 each iteration has its own variable, so closures created in different iterations see different variables (see [Control flow](../../control-flow/2/)).

## Summary

- Everything is passed by value; effects on the caller go through pointers, explicit or hidden.
- `return` with named results assigns first, then runs `defer`.
- `f(s...)` passes the caller's own slice.
- Closures share variables with the function that created them.
- Functions can only be compared with `nil`.
