# Reflection and unsafe — Advanced

What reflection can and can't do at run time, the iterators in `reflect`, why `unsafe` code isn't covered by the compatibility promise, and the rules for pointers passed to C.

## What reflection can create at run time

- new values of any type: `reflect.New(t)`, `reflect.MakeSlice`, `MakeMap`, `MakeChan`;
- **new composite types**: `reflect.SliceOf(t)`, `MapOf(k, v)`, `PointerTo(t)`, `FuncOf(...)`, even `StructOf(fields)`;
- new functions: `reflect.MakeFunc(type, impl)` creates a real, callable function whose implementation receives its arguments as `[]reflect.Value`.

What it **can't** do: create types with new **methods** (`StructOf` can't add methods, so created types can't implement interfaces beyond those promoted through embedded fields), or instantiate generic functions (generics are resolved at compile time).

## Iterators in `reflect` (Go 1.23)

`Value.Seq()` and `Value.Seq2()` return iterators for any value you can `range` over: slices, maps, channels, strings, integers and iterator functions:

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	m := map[string]int{"a": 1}
	for k, v := range reflect.ValueOf(m).Seq2() {
		fmt.Println(k.String(), v.Int())
	}
}
```

## The compatibility promise doesn't cover `unsafe`

Code that depends on the internal layout of runtime types (a map's structure, the fields of a `reflect.Value`, offsets in `runtime.g`) can break with any new Go release. That's what happened when maps switched to Swiss tables (Go 1.24) to libraries that read the `hmap` struct directly. The `//go:linkname` restrictions in Go 1.23 serve the same purpose (see [Packages and modules](../../pachete-module/4/)).

## cgo and pointers

For C calls, the cgo rules require that Go memory passed to C contain no Go pointers (C isn't tracked by the GC), and that C not keep Go pointers after the call. `GODEBUG=cgocheck=1` (the default) checks this partially at run time; `runtime.Pinner` (Go 1.21) pins Go objects so C can reference them for longer.

## `reflect.MakeFunc`: functions built at run time

`MakeFunc` creates a real function, of any type, whose implementation receives its arguments as `[]reflect.Value`. With it you can write a wrapper that works for **any** signature — impossible with generics, which have no variadic type parameters:

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

// withLog replaces the function fptr points to with one that prints its calls.
func withLog(name string, fptr any) {
	fn := reflect.ValueOf(fptr).Elem()
	original := reflect.ValueOf(fn.Interface())
	wrapper := reflect.MakeFunc(fn.Type(), func(args []reflect.Value) []reflect.Value {
		parts := make([]string, len(args))
		for i, a := range args {
			parts[i] = fmt.Sprint(a.Interface())
		}
		res := original.Call(args)
		fmt.Printf("%s(%s) = %v\n", name, strings.Join(parts, ", "), res[0].Interface())
		return res
	})
	fn.Set(wrapper)
}

func main() {
	add := func(a, b int) int { return a + b }
	repeat := strings.Repeat
	withLog("add", &add)
	withLog("repeat", &repeat)

	add(2, 3)
	repeat("ab", 3)
}
```

The cost: every call goes through reflection (allocating argument slices, conversions), tens of times slower than a direct call. For critical code, code generation (`go generate`) gives the same result with no run-time cost.

## When reflection is the right choice

| Need | The usual choice |
|---|---|
| the same logic for several types known at compile time | generics |
| different behavior per type | interfaces |
| **user-defined** structs the library doesn't know (serialization, validation, ORM) | reflection, with a per-type cache |
| maximum performance on types known in advance | code generation |

## Summary

- Reflection can create values, composite types and functions, but not types with new methods.
- `Value.Seq`/`Seq2` (Go 1.23) walk anything you can `range` over.
- Code depending on the runtime's internal layout can break with any release.
- With cgo, memory passed to C holds no Go pointers; `runtime.Pinner` for exceptions.
- `reflect.MakeFunc` builds functions of any type at run time, paying reflection's cost on every call.
