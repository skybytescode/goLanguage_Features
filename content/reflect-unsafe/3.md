# Reflection și unsafe — Avansat

Ce poate și ce nu poate face reflection la rulare, iteratorii din `reflect`, de ce codul cu `unsafe` nu e acoperit de promisiunea de compatibilitate și regulile pentru pointerii transmiși către C.

## Ce poate crea reflection la rulare

- valori noi de orice tip: `reflect.New(t)`, `reflect.MakeSlice`, `MakeMap`, `MakeChan`;
- **tipuri compuse noi**: `reflect.SliceOf(t)`, `MapOf(k, v)`, `PointerTo(t)`, `FuncOf(...)`, chiar `StructOf(campuri)`;
- funcții noi: `reflect.MakeFunc(tip, implementare)` creează o funcție reală, apelabilă, a cărei implementare primește argumentele ca `[]reflect.Value`.

Ce **nu** poate: crea tipuri cu **metode** noi (`StructOf` nu poate adăuga metode, deci tipurile create nu pot implementa interfețe în afară de cele promovate prin câmpuri încorporate), sau instanția funcții generice (generics sunt rezolvate la compilare).

## Iteratori în `reflect` (Go 1.23)

`Value.Seq()` și `Value.Seq2()` întorc iteratori pentru orice valoare care poate fi parcursă cu `range`: slices, maps, channels, stringuri, întregi și funcții iterator:

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	m := map[string]int{"a": 1}
	for k, v := range reflect.ValueOf(m).Seq2() {
		fmt.Println(k.String(), v.Int())
	}
}
```

## Promisiunea de compatibilitate nu acoperă `unsafe`

Codul care depinde de layout-ul intern al tipurilor din runtime (structura unui map, câmpurile unui `reflect.Value`, offset-uri în `runtime.g`) se poate strica la orice versiune nouă de Go. Așa s-a întâmplat la trecerea map-urilor la Swiss tables (Go 1.24) cu bibliotecile care citeau direct structura `hmap`. Restricțiile asupra `//go:linkname` din Go 1.23 au același scop (vezi [Pachete și module](../../pachete-module/4/)).

## cgo și pointerii

La apeluri C, regulile cgo cer ca memoria Go transmisă către C să nu conțină pointeri Go (C nu e urmărit de GC), iar C să nu păstreze pointerii Go după apel. `GODEBUG=cgocheck=1` (implicit) verifică parțial la rulare; `runtime.Pinner` (Go 1.21) fixează obiecte Go ca să poată fi referite din C pe durate mai lungi.

## `reflect.MakeFunc`: funcții construite la rulare

`MakeFunc` creează o funcție reală, de orice tip, a cărei implementare primește argumentele ca `[]reflect.Value`. Cu ea poți scrie un wrapper care funcționează pentru **orice** semnătură — ceva imposibil cu generics, care nu au parametri variadici de tip:

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

// cuLog înlocuiește funcția spre care indică fptr cu una care își afișează apelurile.
func cuLog(nume string, fptr any) {
	fn := reflect.ValueOf(fptr).Elem()
	original := reflect.ValueOf(fn.Interface())
	invelis := reflect.MakeFunc(fn.Type(), func(args []reflect.Value) []reflect.Value {
		parti := make([]string, len(args))
		for i, a := range args {
			parti[i] = fmt.Sprint(a.Interface())
		}
		rez := original.Call(args)
		fmt.Printf("%s(%s) = %v\n", nume, strings.Join(parti, ", "), rez[0].Interface())
		return rez
	})
	fn.Set(invelis)
}

func main() {
	aduna := func(a, b int) int { return a + b }
	repeta := strings.Repeat
	cuLog("aduna", &aduna)
	cuLog("repeta", &repeta)

	aduna(2, 3)
	repeta("ab", 3)
}
```

Costul: fiecare apel trece prin reflection (alocarea slice-urilor de argumente, conversii), de zeci de ori mai lent decât apelul direct. Pentru cod critic, generarea de cod (`go generate`) dă același rezultat fără cost la rulare.

## Când e reflection alegerea potrivită

| Nevoie | Alegerea uzuală |
|---|---|
| aceeași logică pentru mai multe tipuri cunoscute la compilare | generics |
| comportament diferit per tip | interfețe |
| structuri **definite de utilizator**, necunoscute bibliotecii (serializare, validare, ORM) | reflection, cu cache per tip |
| performanță maximă pe tipuri cunoscute dinainte | generare de cod |

## Pe scurt

- Reflection poate crea valori, tipuri compuse și funcții, dar nu tipuri cu metode noi.
- `Value.Seq`/`Seq2` (Go 1.23) parcurg orice se poate parcurge cu `range`.
- Codul care depinde de layout-ul intern al runtime-ului se poate strica la orice versiune.
- La cgo, memoria transmisă către C nu conține pointeri Go; `runtime.Pinner` pentru excepții.
- `reflect.MakeFunc` construiește funcții de orice tip la rulare, cu costul reflection-ului la fiecare apel.
