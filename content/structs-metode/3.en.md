# Structs and methods — Advanced

The exact rules for selecting promoted fields, embedding interfaces, methods as ordinary functions, structs as map keys, and a few struct design techniques used in the standard library itself.

## The depth rule for selectors

For `x.f`, Go looks for `f` at the **shallowest depth**: first the fields and methods of `x`, then those of directly embedded fields, then one level deeper, and so on. If there are **two** matches at the shallowest depth, the selector is ambiguous, but the error only appears if you use it:

```go,compile_fail
package main

type A struct{}

func (A) Name() string { return "A" }

type B struct{}

func (B) Name() string { return "B" }

type C struct {
	A
	B
}

func main() {
	var c C
	_ = c // C compiles just fine...
	println(c.Name()) // ...but here: ambiguous selector c.Name
}
```

The fix is explicit: `c.A.Name()`, or a `Name` method defined on `C`, which hides both.

## Embedding an interface in a struct

A struct can embed an **interface**. The struct then implements the interface, and you override only the methods you care about. This is exactly how `sort.Reverse` is built:

```go
package main

import (
	"fmt"
	"sort"
)

type reverse struct {
	sort.Interface // Len and Swap are delegated
}

func (r reverse) Less(i, j int) bool { return r.Interface.Less(j, i) }

func main() {
	s := []int{3, 1, 2}
	sort.Sort(reverse{sort.IntSlice(s)})
	fmt.Println(s) // [3 2 1]
}
```

Careful: if the embedded interface is `nil`, any method you didn't override panics when called. The technique is also handy in tests, for partial mocks.

## Methods are functions

A method is a function whose first parameter is the receiver. Method expressions make that visible, and allow tables of operations without interfaces:

```go
package main

import "fmt"

type Vector struct{ X, Y float64 }

func (v Vector) Plus(w Vector) Vector  { return Vector{v.X + w.X, v.Y + w.Y} }
func (v Vector) Minus(w Vector) Vector { return Vector{v.X - w.X, v.Y - w.Y} }

func main() {
	ops := map[string]func(Vector, Vector) Vector{
		"+": Vector.Plus,
		"-": Vector.Minus,
	}
	a, b := Vector{1, 2}, Vector{3, 4}
	fmt.Println(ops["+"](a, b), ops["-"](a, b))
}
```

## Comparable structs as map keys

A struct whose fields are all comparable can be a map key. The hash is computed over all fields. It's an efficient replacement for composite keys built with `fmt.Sprintf`:

```go
package main

import "fmt"

type key struct {
	city string
	year int
}

func main() {
	population := map[key]int{
		{"Cluj", 2021}: 286598,
		{"Iași", 2021}: 271692,
	}
	fmt.Println(population[key{"Cluj", 2021}])
}
```

A struct containing a slice, map or function is **not** comparable and can't be a key.

## Techniques from the standard library

**Forcing named initialization.** A blank `_` field prevents positional literals in other packages:

```go,ignore
type Options struct {
	_    struct{} // Options{1, 2} no longer compiles: must be Options{A: 1, B: 2}
	A, B int
}
```

**Forbidding comparison.** A zero-length array-of-functions field makes the struct non-comparable without taking any memory:

```go,ignore
type Token struct {
	_     [0]func() // Token == Token no longer compiles
	value string
}
```

**A "do not copy" marker.** A `noCopy` type with `Lock` and `Unlock` methods makes `go vet` flag copies of the struct, with no run-time cost. That's how `sync.WaitGroup` and `strings.Builder` are protected.

**A zero-size field at the end.** If the last field has zero size (`struct{}`, `[0]int`), the compiler adds padding so a pointer to it doesn't point into the next object in memory. Put such fields first.

**`structs.HostLayout` (Go 1.23).** In theory, the compiler is free to reorder fields. A `_ structs.HostLayout` field requests the platform layout, needed when the struct is passed to C or to the operating system.

## Summary

- Selectors search at minimum depth; ambiguity is an error only when used.
- Embedding an interface gives partial implementations (see `sort.Reverse`).
- Methods are functions with the receiver as the first parameter.
- Comparable structs make excellent map keys.
- `_ struct{}`, `_ [0]func()` and `noCopy` control how a type can be used.
