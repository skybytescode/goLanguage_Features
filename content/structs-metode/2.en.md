# Structs and methods — Practitioner

Go prefers **composition** over inheritance. The main tool is *embedding*. Also here: constructors, useful zero values, tags and the rules about which methods a value can call.

## Embedding: composition, not inheritance

A field with no name (just the type) is an **embedded** field. Its fields and methods are **promoted**: you can use them directly on the outer struct.

```go
package main

import "fmt"

type Address struct {
	City, Street string
}

func (a Address) Full() string { return a.Street + ", " + a.City }

type Customer struct {
	Name    string
	Address // embedded
}

func main() {
	c := Customer{Name: "Ana", Address: Address{City: "Cluj", Street: "Memorandumului 1"}}
	fmt.Println(c.City)   // promoted: c.Address.City
	fmt.Println(c.Full()) // promoted method
}
```

The difference from inheritance: the receiver of a promoted method is still the **inner field**. `Address.Full` knows nothing about `Customer`, and there are no overridden "virtual methods".

```go
package main

import "fmt"

type Animal struct{}

func (Animal) Sound() string   { return "..." }
func (a Animal) Speak() string { return "says " + a.Sound() }

type Dog struct{ Animal }

func (Dog) Sound() string { return "woof" }

func main() {
	d := Dog{}
	fmt.Println(d.Sound()) // woof: Dog's method hides the promoted one
	fmt.Println(d.Speak()) // says ...: Animal.Speak calls Animal.Sound
}
```

If you need polymorphic behavior, use an **interface**, not embedding.

## Constructors

Go has no special constructors. The convention is a `NewT` function that returns a valid value (usually `*T`) and, if needed, an error:

```go
package main

import (
	"errors"
	"fmt"
)

type Range struct {
	min, max int
}

func NewRange(min, max int) (*Range, error) {
	if min > max {
		return nil, errors.New("min > max")
	}
	return &Range{min: min, max: max}, nil
}

func (r *Range) Contains(x int) bool { return x >= r.min && x <= r.max }

func main() {
	r, err := NewRange(1, 10)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(r.Contains(5), r.Contains(11))
}
```

## Make the zero value useful

Many standard library types work right away, with no constructor: `bytes.Buffer`, `strings.Builder`, `sync.Mutex`, `sync.WaitGroup`. Design the same way when you can: a `nil` field can be initialized lazily.

```go
package main

import "fmt"

type Counters struct {
	m map[string]int
}

func (c *Counters) Inc(key string) {
	if c.m == nil {
		c.m = make(map[string]int) // lazy initialization
	}
	c.m[key]++
}

func main() {
	var c Counters // no constructor
	c.Inc("a")
	c.Inc("a")
	fmt.Println(c.m["a"]) // 2
}
```

## Method sets: which methods a value has

- Type `T` has only the **value** receiver methods in its method set.
- Type `*T` has the value receiver methods **and** the pointer receiver ones.

When you call `v.M()` on a variable, Go takes the address automatically (`(&v).M()`) if needed. This only works for **addressable** values. Map elements and values returned by functions are not addressable:

```go,compile_fail
package main

type Counter struct{ n int }

func (c *Counter) Inc() { c.n++ }

func main() {
	m := map[string]Counter{"a": {}}
	m["a"].Inc() // error: cannot call pointer method Inc on Counter
}
```

The rule matters most for interfaces: if the methods are on `*T`, only `*T` implements the interface, not `T`. See [Interfaces](../../interfete/2/).

## Don't copy structs that contain a mutex

Copying a struct copies its mutex too, state and all. `go vet` (the `copylocks` analyzer) catches these cases:

```go,ignore
type Cache struct {
	mu   sync.Mutex
	data map[string]string
}

func (c Cache) Get(k string) string { // vet: Get passes lock by value
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.data[k]
}
```

The fix: a pointer receiver (`func (c *Cache) Get`).

## Tags

Fields can have **tags**: strings read via reflection by packages such as `encoding/json`:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Product struct {
	ID       int     `json:"id"`
	Name     string  `json:"name"`
	Price    float64 `json:"price,omitempty"`
	internal string  // unexported: ignored by json
}

func main() {
	b, _ := json.Marshal(Product{ID: 1, Name: "book", internal: "x"})
	fmt.Println(string(b)) // {"id":1,"name":"book"}
}
```

## The empty struct

`struct{}` takes **zero** bytes. It's used as the value in sets (`map[string]struct{}`) and as a signal on channels (`chan struct{}`).

## Summary

- Embedding promotes fields and methods, but it isn't inheritance.
- `NewT` for validation; otherwise, make the zero value usable.
- `T` has only value receiver methods; `*T` has them all.
- Don't copy structs with a mutex; `go vet` helps.
- Tags control serialization.
