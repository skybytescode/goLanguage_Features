# Structs și metode — Expert

Ce generează compilatorul pentru structuri și metode: wrapper-ele metodelor promovate, funcțiile de egalitate, copierea și zero-area memoriei, și când copierea unei structuri devine costisitoare.

## Metode promovate = wrapper-e generate

Pentru fiecare metodă promovată, compilatorul generează o funcție „wrapper” pe tipul exterior care calculează adresa câmpului încorporat și apelează metoda reală. Wrapper-ele apar în stack trace-uri cu `<autogenerated>`. Dacă încorporezi un **pointer** (`*Adresa`), wrapper-ul îl dereferențiază, deci un pointer `nil` încorporat dă panic la apel.

Method sets la embedding:

| Încorporezi | `S` primește | `*S` primește |
|---|---|---|
| `T` | metodele lui `T` | metodele lui `T` și `*T` |
| `*T` | metodele lui `T` și `*T` | metodele lui `T` și `*T` |

## Costul copierii

Structurile se copiază la atribuire, la trecerea ca argument și în `range`. Pentru structuri mari (sute de octeți), receptorii pointer și `for i := range s` evită copii repetate. Pentru structuri mici (câteva cuvinte), valoarea e de obicei **mai rapidă**: stă în registre, nu necesită dereferențiere și nu scapă pe heap.

## Egalitatea: funcții generate

`a == b` pe două structuri nu e magie: compilatorul generează o funcție de egalitate per tip (simbolurile `type:.eq.main.T` din binar), folosită și de map-uri și de comparația interfețelor.

- Dacă structura nu are padding și conține doar tipuri comparate „pe biți” (întregi, pointeri, booleeni), egalitatea devine un singur `memequal` pe toată memoria.
- Câmpurile `float` (unde `+0 == -0`, iar `NaN != NaN`), stringurile (lungime, apoi conținut) și interfețele (tip, apoi `Equal`-ul tipului) cer comparații separate.
- Padding-ul **nu** e comparat: conținutul lui e nedefinit, de aceea compilatorul nu poate folosi `memequal` pe structuri cu „găuri”.

Ordinea câmpurilor contează deci de două ori: pentru dimensiune și pentru costul comparației.

## Copierea și zero-area

Atribuirea unei structuri e o copiere de memorie. Compilatorul alege implementarea după dimensiune:

| Dimensiune | Cod generat (amd64) |
|---|---|
| câteva cuvinte | instrucțiuni `MOVQ`/`MOVUPS` inline, uneori doar registre |
| zeci–sute de octeți | secvențe desfăcute de instrucțiuni SIMD sau bucle scurte (istoric prin „Duff's device”: `DUFFCOPY`/`DUFFZERO`) |
| mari | apel `runtime.memmove` / `memclrNoHeapPointers` |

Dacă structura conține pointeri și destinația e pe heap, copierea trebuie să treacă și prin write barrier cât timp GC-ul marchează (`typedmemmove`), ceea ce o face mai scumpă decât copierea datelor fără pointeri.

## Câmpurile încorporate în memorie

Embedding-ul nu e un mecanism special la rulare: un câmp încorporat e un câmp **obișnuit**, fără nume, așezat în structură ca oricare altul. Câmpurile promovate sunt doar o scurtătură de sintaxă pentru un offset:

```go
package main

import (
	"fmt"
	"unsafe"
)

type Adresa struct {
	Oras, Strada string
}

type Client struct {
	ID     int64
	Adresa // încorporat prin valoare: 32 de octeți în interiorul lui Client
	Activ  bool
}

type ClientPtr struct {
	ID      int64
	*Adresa // încorporat prin pointer: 8 octeți și o dereferențiere la acces
}

func main() {
	var c Client
	fmt.Println(unsafe.Offsetof(c.Adresa), unsafe.Offsetof(c.Oras), unsafe.Offsetof(c.Strada)) // 8 8 24
	fmt.Println(unsafe.Sizeof(c), unsafe.Sizeof(ClientPtr{}))                                  // 48 16
}
```

`c.Oras` se compilează exact ca `c.Adresa.Oras`: o adresă de bază plus offsetul 8, fără niciun apel sau căutare. Cu un câmp încorporat prin **pointer**, accesul cere o dereferențiere în plus (și dă panic dacă pointerul e `nil`), iar structura exterioară nu mai conține datele, doar adresa lor.

## Pe scurt

- Metodele promovate sunt wrapper-e generate de compilator (`<autogenerated>`).
- `==` pe structuri folosește funcții de egalitate generate; fără padding devine `memequal`.
- Copierea alege între instrucțiuni inline, secvențe SIMD și `memmove` după dimensiune.
- Structurile mici se copiază practic gratuit; cele mari merită pointeri sau `range` cu index.
- Un câmp încorporat e un câmp obișnuit; accesul la câmpurile promovate e un simplu offset.
