# Generics — Expert

How Go compiles generic code: GC shape stenciling with dictionaries, what a dictionary contains, how to recognize instantiations in profiles, and when generic code is faster or slower than the interface-based alternative.

## Implementation: GC shape stenciling + dictionaries

There are two classic strategies:

- **monomorphization** (C++, Rust): one copy of the code per type; fast, but big binaries and slow compilation;
- **boxing** (Java): a single copy, everything through pointers and dynamic dispatch; compact, but slow.

Go chose a middle ground. The compiler generates one copy per **GC shape** — types with the same memory representation from the allocator's and the GC's point of view. `int` and `int64` share a shape on 64-bit; a defined type `type ID int` has `int`'s shape; and, importantly, **all pointer types share a single shape**.

Each copy receives a hidden **dictionary** as its first argument, holding information specific to the concrete type: the type descriptor, the `itab`s for the constraint's methods, the equality and hash functions.

```go,ignore
// what you write
func Sum[T Number](s []T) T

// roughly what the compiler generates
func Sum[go.shape.int](dict *dictionary, s []int) int
func Sum[go.shape.float64](dict *dictionary, s []float64) float64
```

## The consequence: methods on pointer types go through the dictionary

For value types (`int`, `float64`, structs), each shape gets specialized code; arithmetic and comparisons are direct. For pointer types, they all share the **same** copy, and a call to a constraint method becomes an indirect call through the dictionary — similar to an interface call, but with one extra level of indirection:

```go,ignore
func Show[T fmt.Stringer](v T) string {
	return v.String() // for T = *Person: an indirect call through the dictionary, no inlining
}
```

The practical conclusion: generics are excellent for **data structures** and algorithms over value types. For code that just calls methods, a plain interface is as fast or faster, and the compiler can devirtualize it more easily. Benchmark before "optimizing" by switching to generics.

## What a dictionary contains

The dictionary passed to each instantiation is a statically generated structure, one per **concrete combination** of type arguments (`Sum[int]` and `Sum[MyInt]` have different dictionaries, even though they share code). It contains:

- the type descriptors of the arguments (for allocation, `reflect`, conversions to interfaces);
- the `itab`s needed for the constraint's methods;
- **sub-dictionaries** for generic functions called further down with derived types (for example a `Sum[T]` that calls `slices.Sort[[]T]`).

In profiles and in `objdump`, instantiations show up with the shape name: `main.Sum[go.shape.int]`, `main.Show[go.shape.*uint8]` (all pointers). When you see a single `go.shape.*uint8` function eating a lot of CPU, it's the code shared by **every** pointer instantiation.

## Generics vs. interfaces, measured

```go
package main

import (
	"fmt"
	"testing"
)

type Number interface{ ~int | ~float64 }

func GenericSum[T Number](s []T) T {
	var t T
	for _, v := range s {
		t += v
	}
	return t
}

type Valuer interface{ Value() int }

type Int int

func (i Int) Value() int { return int(i) }

func InterfaceSum(s []Valuer) int {
	t := 0
	for _, v := range s {
		t += v.Value() // an indirect call for every element
	}
	return t
}

func main() {
	nums := make([]int, 10_000)
	ifs := make([]Valuer, 10_000)
	for i := range nums {
		nums[i] = i
		ifs[i] = Int(i)
	}
	g := testing.Benchmark(func(b *testing.B) {
		for b.Loop() {
			GenericSum(nums)
		}
	})
	f := testing.Benchmark(func(b *testing.B) {
		for b.Loop() {
			InterfaceSum(ifs)
		}
	})
	fmt.Printf("generic: %v/op   interface: %v/op\n", g.NsPerOp(), f.NsPerOp())
}
```

On a value type (`int`), the generic version gets specialized code: a tight, vectorizable loop over contiguous data. The interface version makes one indirect call per element and has scattered data (each `Int` in an interface is stored separately in memory). The difference vanishes or reverses when `T` is a pointer type and the function only calls methods.

## Summary

- One code copy per GC shape, plus one dictionary per concrete instantiation.
- Every pointer type shares the `go.shape.*uint8` shape: methods are called indirectly.
- Dictionaries hold type descriptors, `itab`s and sub-dictionaries.
- On value types, generics beat interfaces; on pointers with methods, not necessarily.
