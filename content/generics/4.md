# Generics — Expert

Cum compilează Go codul generic: GC shape stenciling cu dicționare, ce conține un dicționar, cum recunoști instanțierile în profiluri și când codul generic e mai rapid sau mai lent decât varianta cu interfețe.

## Implementarea: GC shape stenciling + dicționare

Există două strategii clasice:

- **monomorfizare** (C++, Rust): o copie a codului pentru fiecare tip; rapid, dar binare mari și compilare lentă;
- **boxing** (Java): o singură copie, totul prin pointeri și dispatch dinamic; compact, dar lent.

Go a ales un compromis. Compilatorul generează câte o copie pentru fiecare **GC shape** — tipurile cu aceeași reprezentare în memorie din perspectiva alocatorului și a GC-ului. `int` și `int64` au aceeași formă pe 64 de biți; un tip definit `type ID int` are forma lui `int`; și, important, **toate tipurile pointer au aceeași formă**.

Fiecare copie primește un **dicționar** ascuns, ca prim argument, cu informațiile specifice tipului concret: descriptorul de tip, `itab`-urile pentru metodele din constrângere, funcțiile de egalitate și hash.

```go,ignore
// ce scrii
func Suma[T Numar](s []T) T

// aproximativ ce generează compilatorul
func Suma[go.shape.int](dict *dictionary, s []int) int
func Suma[go.shape.float64](dict *dictionary, s []float64) float64
```

## Consecința: metodele pe tipuri pointer trec prin dicționar

Pentru tipuri valoare (`int`, `float64`, structuri), fiecare formă are cod specializat; operațiile aritmetice și comparațiile sunt directe. Pentru tipuri pointer, toate împart **aceeași** copie, iar un apel de metodă din constrângere devine un apel indirect, prin dicționar — similar cu un apel prin interfață, dar cu un nivel de indirectare în plus:

```go,ignore
func Afiseaza[T fmt.Stringer](v T) string {
	return v.String() // pentru T = *Persoana: apel indirect prin dicționar, fără inlining
}
```

Concluzia practică: generics sunt excelente pentru **structuri de date** și algoritmi pe tipuri valoare. Pentru cod care doar apelează metode, o interfață simplă e la fel de rapidă sau mai rapidă, iar compilatorul o poate devirtualiza mai ușor. Măsoară cu benchmark-uri înainte de a „optimiza” trecând la generics.

## Ce conține un dicționar

Dicționarul transmis fiecărei instanțieri e o structură generată static, câte una per **combinație concretă** de argumente de tip (`Suma[int]`, `Suma[MyInt]` au dicționare diferite, chiar dacă împart codul). Conține:

- descriptorii de tip ai argumentelor (pentru alocări, `reflect`, conversii la interfață);
- `itab`-urile necesare pentru metodele din constrângere;
- **sub-dicționare** pentru funcțiile generice apelate mai departe cu tipuri derivate (de exemplu `Suma[T]` care apelează `slices.Sort[[]T]`).

În profiluri și în `objdump`, instanțierile apar cu numele formei: `main.Suma[go.shape.int]`, `main.Afiseaza[go.shape.*uint8]` (toți pointerii). Când vezi o singură funcție `go.shape.*uint8` care consumă mult CPU, e codul partajat de **toate** instanțierile cu pointeri.

## Generics vs. interfețe, măsurat

```go
package main

import (
	"fmt"
	"testing"
)

type Numar interface{ ~int | ~float64 }

func SumaGenerica[T Numar](s []T) T {
	var t T
	for _, v := range s {
		t += v
	}
	return t
}

type Adunabil interface{ Valoare() int }

type Int int

func (i Int) Valoare() int { return int(i) }

func SumaInterfata(s []Adunabil) int {
	t := 0
	for _, v := range s {
		t += v.Valoare() // apel indirect pentru fiecare element
	}
	return t
}

func main() {
	nums := make([]int, 10_000)
	ifs := make([]Adunabil, 10_000)
	for i := range nums {
		nums[i] = i
		ifs[i] = Int(i)
	}
	g := testing.Benchmark(func(b *testing.B) {
		for b.Loop() {
			SumaGenerica(nums)
		}
	})
	f := testing.Benchmark(func(b *testing.B) {
		for b.Loop() {
			SumaInterfata(ifs)
		}
	})
	fmt.Printf("generic: %v/op   interfață: %v/op\n", g.NsPerOp(), f.NsPerOp())
}
```

Pe un tip valoare (`int`), varianta generică primește cod specializat: o buclă strânsă, vectorizabilă, cu datele contigue. Varianta cu interfețe face un apel indirect per element și are datele împrăștiate (fiecare `Int` din interfață e pus deoparte în memorie). Diferența dispare sau se inversează când `T` e un tip pointer și funcția doar apelează metode.

## Pe scurt

- O copie de cod per GC shape, plus un dicționar per instanțiere concretă.
- Toate tipurile pointer împart forma `go.shape.*uint8`: metodele sunt apelate indirect.
- Dicționarele conțin descriptori de tip, `itab`-uri și sub-dicționare.
- Pe tipuri valoare, generics bat interfețele; pe pointeri cu metode, nu neapărat.
