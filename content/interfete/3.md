# Interfețe — Avansat

Regulile mai fine ale interfețelor: de ce o interfață cu un pointer `nil` nu e `nil`, conversiile statice și dinamice între interfețe, interfețele încorporate, comparația care poate da panic, type set-urile și interfețele „sigilate”.

## De ce o interfață cu `nil` înăuntru nu e `nil`

Capcana de la nivelul Practician vine dintr-o decizie de design: o interfață ține **perechea** (tip dinamic, valoare). Un pointer `nil` de tip `*T` e o valoare perfect validă — metodele lui pot fi apelate (vezi [Pointeri](../../pointeri/2/)) — deci interfața care îl conține știe ce metode să apeleze și **nu** e goală.

```go
package main

import "fmt"

type Lista struct{ urm *Lista }

func (l *Lista) Len() int {
	if l == nil {
		return 0 // o metodă validă pe un receptor nil
	}
	return 1 + l.urm.Len()
}

type Lungimer interface{ Len() int }

func main() {
	var l *Lista
	var i Lungimer = l
	fmt.Println(i == nil, i.Len()) // false 0: interfața are tip, iar metoda funcționează
}
```

Dacă `i == nil` ar fi `true` aici, apelul `i.Len()` ar trebui să dea panic, deși metoda tratează explicit cazul `nil`. Go a ales consistența: o interfață e `nil` doar când nu are tip.

## Conversii între interfețe: statice și dinamice

- **Statică**: din `io.ReadWriter` în `io.Reader`. Compilatorul știe că orice `ReadWriter` e și `Reader`; conversia nu poate eșua.
- **Dinamică**: din `io.Reader` în `io.Writer`, cu type assertion. Reușește doar dacă **tipul concret** din interfață are și metoda `Write`:

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"strings"
)

func main() {
	var r io.Reader = &bytes.Buffer{}
	_, ok := r.(io.Writer) // tipul concret *bytes.Buffer are Write
	fmt.Println(ok)        // true

	r = strings.NewReader("x")
	_, ok = r.(io.Writer) // *strings.Reader nu are Write
	fmt.Println(ok)       // false
}
```

Asta permite „upgrade”-urile de interfață (`io.WriterTo`, `http.Flusher`) — dar și ascunderea lor accidentală când un tip e învelit într-un wrapper care nu le reexpune.

## Interfețe încorporate cu metode comune

Din Go 1.14, o interfață poate încorpora alte interfețe care au **aceeași** metodă, cu aceeași semnătură; metoda apare o singură dată:

```go
package main

import (
	"fmt"
	"io"
)

type ReadCloser interface {
	io.Reader
	io.Closer
}

type WriteCloser interface {
	io.Writer
	io.Closer
}

type ReadWriteCloser interface {
	ReadCloser
	WriteCloser // Close apare de două ori: permis din Go 1.14
}

func main() {
	var rwc ReadWriteCloser
	fmt.Println(rwc == nil)
}
```

Două metode cu același nume și semnături **diferite** rămân o eroare de compilare.

## Comparația interfețelor poate da panic

Două interfețe sunt egale dacă au același tip dinamic și valori egale. Dacă tipul dinamic **nu e comparabil** (slice, map, funcție), comparația dă **panic la rulare**, chiar dacă la compilare totul e în regulă:

```go,panic
package main

import "fmt"

func main() {
	var a, b any = []int{1}, []int{1}
	fmt.Println(a == b) // panic: runtime error: comparing uncomparable type []int
}
```

Același panic apare la folosirea unei asemenea valori drept cheie într-un `map[any]T`. Constrângerea generică `comparable` acceptă interfețe (din Go 1.20) tocmai cu acest risc.

## Interfețe cu type sets

De la generics (Go 1.18), o interfață poate conține și **termeni de tip**:

```go,ignore
type Numar interface {
	~int | ~int64 | ~float64
}
```

Asemenea interfețe pot fi folosite **doar** ca constrângeri pentru parametri de tip, nu ca tipuri de variabile. Detalii în [Generics](../../generics/2/).

## Metode neexportate: interfețe „sigilate”

O interfață care conține o metodă **neexportată** nu poate fi implementată în afara pachetului ei. E modul Go de a obține un set închis de implementări (un „sum type” restrâns):

```go,ignore
package forma

type Forma interface {
	Arie() float64
	sigilat() // doar tipurile din pachetul forma o pot implementa
}
```

Un tip din alt pachet o poate „implementa” doar încorporând o valoare care deja o implementează.

## Pe scurt

- O interfață e `nil` doar fără tip; un pointer `nil` cu metode e o valoare validă.
- Conversiile spre interfețe mai mici sunt statice; cele „laterale” sunt type assertions dinamice.
- Interfețele încorporate pot avea metode identice comune (Go 1.14).
- `==` pe interfețe cu tip dinamic necomparabil dă panic.
- Type set-urile sunt doar pentru constrângeri; metodele neexportate „sigilează” o interfață.
