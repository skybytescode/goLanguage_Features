# Interfaces — Advanced

The finer rules of interfaces: why an interface holding a `nil` pointer isn't `nil`, static and dynamic conversions between interfaces, embedded interfaces, comparisons that can panic, type sets and "sealed" interfaces.

## Why an interface with `nil` inside isn't `nil`

The Practitioner level's trap comes from a design decision: an interface holds a **pair** (dynamic type, value). A `nil` pointer of type `*T` is a perfectly valid value — its methods can be called (see [Pointers](../../pointeri/2/)) — so the interface holding it knows which methods to call and is **not** empty.

```go
package main

import "fmt"

type List struct{ next *List }

func (l *List) Len() int {
	if l == nil {
		return 0 // a valid method on a nil receiver
	}
	return 1 + l.next.Len()
}

type Lener interface{ Len() int }

func main() {
	var l *List
	var i Lener = l
	fmt.Println(i == nil, i.Len()) // false 0: the interface has a type, and the method works
}
```

If `i == nil` were `true` here, the call `i.Len()` would have to panic, even though the method explicitly handles `nil`. Go chose consistency: an interface is `nil` only when it has no type.

## Conversions between interfaces: static and dynamic

- **Static**: from `io.ReadWriter` to `io.Reader`. The compiler knows every `ReadWriter` is also a `Reader`; the conversion can't fail.
- **Dynamic**: from `io.Reader` to `io.Writer`, with a type assertion. It succeeds only if the **concrete type** inside the interface also has a `Write` method:

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"strings"
)

func main() {
	var r io.Reader = &bytes.Buffer{}
	_, ok := r.(io.Writer) // the concrete *bytes.Buffer has Write
	fmt.Println(ok)        // true

	r = strings.NewReader("x")
	_, ok = r.(io.Writer) // *strings.Reader has no Write
	fmt.Println(ok)       // false
}
```

This enables interface "upgrades" (`io.WriterTo`, `http.Flusher`) — but also hiding them by accident when a type is wrapped in something that doesn't re-expose them.

## Embedded interfaces with shared methods

Since Go 1.14, an interface can embed other interfaces that share **the same** method with the same signature; the method appears only once:

```go
package main

import (
	"fmt"
	"io"
)

type ReadCloser interface {
	io.Reader
	io.Closer
}

type WriteCloser interface {
	io.Writer
	io.Closer
}

type ReadWriteCloser interface {
	ReadCloser
	WriteCloser // Close appears twice: allowed since Go 1.14
}

func main() {
	var rwc ReadWriteCloser
	fmt.Println(rwc == nil)
}
```

Two methods with the same name and **different** signatures are still a compile error.

## Comparing interfaces can panic

Two interfaces are equal if they have the same dynamic type and equal values. If the dynamic type **isn't comparable** (slice, map, function), the comparison **panics at run time**, even though everything is fine at compile time:

```go,panic
package main

import "fmt"

func main() {
	var a, b any = []int{1}, []int{1}
	fmt.Println(a == b) // panic: runtime error: comparing uncomparable type []int
}
```

The same panic happens when such a value is used as a key in a `map[any]T`. The generic `comparable` constraint accepts interfaces (since Go 1.20) with exactly this risk.

## Interfaces with type sets

Since generics (Go 1.18), an interface can also contain **type terms**:

```go,ignore
type Number interface {
	~int | ~int64 | ~float64
}
```

Such interfaces can be used **only** as constraints for type parameters, not as variable types. Details in [Generics](../../generics/2/).

## Unexported methods: "sealed" interfaces

An interface containing an **unexported** method can't be implemented outside its package. It's Go's way to get a closed set of implementations (a limited "sum type"):

```go,ignore
package shape

type Shape interface {
	Area() float64
	sealed() // only types in package shape can implement it
}
```

A type from another package can only "implement" it by embedding a value that already does.

## Summary

- An interface is `nil` only when it has no type; a `nil` pointer with methods is a valid value.
- Conversions to smaller interfaces are static; "sideways" ones are dynamic type assertions.
- Embedded interfaces may share identical methods (Go 1.14).
- `==` on interfaces with a non-comparable dynamic type panics.
- Type sets are for constraints only; unexported methods "seal" an interface.
